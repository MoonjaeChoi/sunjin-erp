## 1. 제안 개요

### 1.1 제안 배경

엘리에셀 교회의 교인 수 증가와 교회 행정 업무 복잡도 증대에 따라, 기존 수기·스프레드시트 기반 행정 방식으로는 효율적인 교회 운영이 어려워지고 있습니다. 본 제안서는 선진인포텍이 자체 개발한 **watching** 시스템을 엘리에셀 교회에 맞게 구축·운영함으로써 교회 행정의 디지털화를 실현하는 방안을 제시합니다.

### 1.2 제안 범위

- 교인 정보 통합 관리 시스템 구축
- 13개 핵심 모듈 커스터마이징 및 배포
- 전담 서버 환경 구성 및 데이터 이관
- 사용자 교육 및 운영 지원

### 1.3 제안 방식

| 구분 | 내용 |
|------|------|
| 개발 방식 | 기존 watching 플랫폼 기반 커스터마이징 |
| 배포 방식 | 온프레미스 (교회 내 서버) 또는 클라우드 선택 |
| 운영 방식 | 연간 유지보수 계약 (선택) |

## 2. 현황 분석 및 도입 필요성

### 2.1 주요 문제점

| 현황 | 문제점 | 영향 |
|------|--------|------|
| 교인 정보 관리 | 엑셀·수기 장부 분산 관리 | 데이터 중복·누락, 조회 불편 |
| 출석 관리 | 종이 출석부 수기 집계 | 통계 오류, 결석자 파악 지연 |

| 보고 업무 | 각 부서별 개별 문서 제출 | 취합·검토 비효율 |
| 문자 발송 | 외부 서비스 개별 계약·수동 발송 | 교인 명단과 이중 관리 |
| 통계 | 수작업 집계 | 데이터 신뢰성 낮음, 시간 과다 소모 |

## 3. 시스템 구성

### 3.1 전체 아키텍처

```
┌─────────────────────────────────────────────────────────────┐
│                      사용자 접근 계층                         │
│   PC 브라우저 (Chrome / Edge)   스마트폰 (반응형 웹)          │
└───────────────────────┬─────────────────────────────────────┘
                        │ HTTPS
┌───────────────────────▼─────────────────────────────────────┐
│                    웹 애플리케이션 서버                        │
│   Next.js 14 (App Router) + TypeScript                       │
│   ├─ 프론트엔드: shadcn/ui + Tailwind CSS                    │
│   ├─ 백엔드 API: Next.js Route Handlers (REST)               │
│   ├─ 인증: NextAuth.js (JWT 세션 + 역할 기반 권한)           │
│   └─ ORM: TypeORM (Oracle 네이티브 연결)                     │
└───────────────────────┬─────────────────────────────────────┘
                        │
┌───────────────────────▼─────────────────────────────────────┐
│                      데이터베이스                             │
│   Oracle XE 21c                                              │
│   ├─ 교인 정보 / 출결 / 심방 / 보고 / 교육 / 봉사           │
│   ├─ 통계 / 게시판 / 교구 / 사용자 권한                     │
│   └─ 소프트 삭제 (deleted_at) · 변경 이력 보존              │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 기술 스택

| 계층 | 기술 | 비고 |
|------|------|------|
| **Frontend** | Next.js 14 + TypeScript | SSR/SSG, 파일 기반 라우팅 |
| **UI** | shadcn/ui + Tailwind CSS | 반응형, 다크모드 지원 |
| **상태 관리** | Zustand + TanStack Query | 클라이언트/서버 상태 분리 |
| **Backend API** | Next.js Route Handlers | REST API, 별도 서버 불필요 |
| **ORM** | TypeORM 0.3.x | Oracle 공식 지원, 마이그레이션 |
| **Database** | Oracle XE 21c | 무료 라이선스, 엔터프라이즈급 |
| **인증** | NextAuth.js (JWT) | 역할 기반 접근 제어 |
| **배포** | Docker + Docker Compose | 온프레미스·클라우드 공통 |
| **문자** | 외부 SMS API 연동 | 별도 서비스 신청 필요 |

### 3.3 인프라 구성

#### 옵션 A: 온프레미스 (교회 내 서버)

```
교회 내 서버 1대
├─ CPU: Intel Core i5 이상 (4코어)
├─ RAM: 16GB 이상
├─ Storage: SSD 500GB 이상
├─ OS: Ubuntu 22.04 LTS
├─ Docker 환경 (앱 컨테이너 + DB 컨테이너)
└─ UPS (무정전전원장치) 권장
```

| 항목 | 사양 | 예상 비용 |
|------|------|---------|
| 서버 PC/NUC | i5 / 16GB RAM / 512GB SSD | 100~150만원 |
| UPS | 500VA급 | 10~15만원 |
| 공인 IP / 도메인 | 유동 IP + DDNS 또는 고정 IP | 0~5만원/월 |

#### 옵션 B: 클라우드 (NCP / AWS / Oracle Cloud)

```
클라우드 VM 1대
├─ 2 vCPU / 8GB RAM / 100GB SSD
├─ Oracle XE 21c (컨테이너)
├─ Next.js 앱 (컨테이너)
└─ SSL 인증서 (Let's Encrypt 무료)
```

| 공급사 | 사양 | 월 비용 (예상) |
|--------|------|--------------|
| NCP (Naver Cloud) | 2vCPU/8GB | 약 5~8만원/월 |
| AWS Lightsail | 2vCPU/8GB | 약 4~6만원/월 |
| Oracle Cloud Free Tier | 4 OCPU/24GB | **무료** (조건부) |

### 3.4 보안 구성

| 항목 | 적용 내용 |
|------|---------|

### 4.2 주요 모듈 상세

#### 모듈 2: 교인 관리
- **교인 등록**: 기본정보 → 추가정보 → 완료 3단계 마법사
- **교인 검색**: 이름·성별·나이·소속·직분·지역 등 다중 조건 조합
- **교인 목록**: 조직 트리 기반 부서별 필터, 엑셀 내보내기
- **새가족 앱 연동**: 스마트 성도 앱 등록요청·수정요청 승인 처리
- **제적 관리**: 제적 사유·복적 처리

#### 모듈 3: 출결 관리
- **QR/바코드 스캔**: 예배 현장 실시간 체크인, 생일 알림
- **주간 출결**: 날짜 기준 주간 현황, 소속별·봉사별 구분
- **결석자 파악**: 연속 결석자 필터링 (전주 출석 옵션)

#### 모듈 8: 통계
- **출석률**: 원형 차트, 연도별 새신자 현황, 예배별 평균
- **심방 통계**: 심방자별 월별 건수, 유형별 집계
- **환경별 접속**: 디바이스·브라우저 분포

#### 모듈 13: 프로그램 설정 (관리자 전용)
- 교회명·담임목사·로고·직인 등록
- 조직 구조·교육 과정·코드 항목 정의
- 사용자 계정 생성, 그룹별 메뉴 접근 권한 설정
