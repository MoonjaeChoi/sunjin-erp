# Product Requirement Document: 공지사항 (게시판)

문서번호: 2101
작성일: 2026-01-25
상위문서: 1000_초안.prd

## 1. Overview

본 PRD는 sunjin-erp 시스템의 "공지사항 (게시판)" 기능에 대한 요구사항을 정의한다.
이 기능은 다양한 유형(공지, 공유, 지시, 건의, 자유)의 게시물을 분류하여 게시하고, 조회수 통계 및 댓글/답글 피드백 기능을 통해 조직 내 의사소통을 촉진하는 게시판 시스템을 제공한다.

**대상 모듈:** 공지사항 (게시판)
**대상 사용자 역할:** USER (조회, 댓글 작성), MANAGER (신규 게시물 작성, 자신의 게시물 수정), ADMIN (전체 관리 및 삭제)

## 2. Goals & Objectives

* **조직 내 의사소통 증진:** 다양한 유형의 공지사항을 통일된 플랫폼에서 관리하여 정보 전달 효율성 향상
* **유형별 게시판 분류:** 공지, 공유, 지시, 건의, 자유 게시판으로 구분하여 정보 체계화
* **조회수 및 인기도 추적:** 게시물별 조회수를 통계하여 핫이슈 파악 및 사용자 관심도 측정
* **양방향 피드백 시스템:** 댓글 및 답글 기능으로 게시물에 대한 질의응답 및 토론 지원
* **권한 기반 콘텐츠 관리:** 게시물 작성/수정/삭제 권한을 명확히 정의하여 무분별한 게시 방지
* **검색 및 필터링:** 게시판 유형, 작성자, 작성 날짜 등으로 쉽게 필터링하여 필요한 정보 빠르게 접근
* **실시간 업데이트:** 새로운 게시물, 댓글 추가 시 목록 자동 갱신

## 3. User Stories / Use Cases

* **US-1:** 일반 사용자로서, 공지사항 목록을 조회하고 게시판 유형(공지, 공유, 지시, 건의, 자유)으로 필터링할 수 있다. 그래서 필요한 정보를 빠르게 찾을 수 있다.
    * *Acceptance Criteria:*
        * 공지사항 목록 페이지에 모든 유형의 게시물 표시 (최신순)
        * 게시판 유형별 탭 또는 필터 제공
        * 게시물에 제목, 작성자, 작성일, 조회수, 댓글 수 표시
        * 페이지네이션 지원 (20개 항목 기본, 최대 100)
        * 정렬 지원: 최신순, 조회수순, 댓글순

* **US-2:** 일반 사용자로서, 게시물 상세 정보를 조회하고 댓글을 작성할 수 있다. 그래서 다른 직원들과 소통할 수 있다.
    * *Acceptance Criteria:*
        * 게시물 상세 페이지에 제목, 내용, 작성자, 작성일, 수정일, 조회수, 게시판 유형 표시
        * 첨부파일 다운로드 링크 제공 (이미지, PDF, 문서 등)
        * 댓글 목록 표시 (최신순, 페이지네이션)
        * 댓글 작성 폼 제공 (작성자 자동 입력, 내용 텍스트에어리어)
        * 댓글 작성 시 실시간 목록 갱신

* **US-3:** 일반 사용자로서, 댓글에 대한 답글(대댓글)을 작성할 수 있다. 그래서 특정 댓글에 대한 피드백을 줄 수 있다.
    * *Acceptance Criteria:*
        * 각 댓글에 "답글 작성" 버튼 제공
        * 답글 폼은 댓글 바로 아래에 인라인으로 표시
        * 답글 작성 시 "@원댓글작성자" 멘션 자동 추가 (선택)
        * 답글은 원댓글 아래 들여쓰기로 표시 (최대 1단계, 답글의 답글은 불가)
        * 실시간 갱신

* **US-4:** 매니저로서, 새로운 게시물을 작성할 수 있다. 그래서 팀 또는 조직에 정보를 공유할 수 있다.
    * *Acceptance Criteria:*
        * 게시물 작성 폼에서 게시판 유형, 제목, 내용 입력
        * 내용은 WYSIWYG 에디터 또는 마크다운 에디터 지원 (선택)
        * 파일 첨부 가능 (최대 5개, 각 10MB 제한)
        * 미리보기 기능 제공
        * 작성 시 작성자, 작성일 자동 입력
        * 임시 저장 기능 (localStorage 또는 DB)

* **US-5:** 매니저로서, 자신이 작성한 게시물을 수정하고 삭제할 수 있다. 그래서 게시된 정보를 관리할 수 있다.
    * *Acceptance Criteria:*
        * 자신의 게시물에 "수정", "삭제" 버튼 표시
        * 수정 시 기존 내용이 폼에 로드되어 편집 가능
        * 수정 완료 시 "수정일" 업데이트
        * 삭제 시 확인 대화 표시
        * 삭제는 soft delete (복구 가능, Phase 2)

* **US-6:** 사용자로서, 자신이 작성한 댓글을 수정하고 삭제할 수 있다.
    * *Acceptance Criteria:*
        * 자신의 댓글에 "수정", "삭제" 버튼 표시
        * 다른 사용자의 댓글은 버튼 비활성화
        * 수정 시 확인 모달에서 내용 편집
        * 삭제 시 확인 대화 표시 (soft delete)

* **US-7:** 관리자로서, 모든 게시물을 조회하고 필요시 삭제할 수 있다. 그래서 부적절한 콘텐츠를 관리할 수 있다.
    * *Acceptance Criteria:*
        * 게시물 목록에 "관리자" 필터 제공 (ADMIN만 표시)
        * 모든 게시물에 "삭제" 버튼 표시 (hard delete 또는 soft delete)
        * 삭제 이유 입력 옵션 (선택)
        * 삭제 이력 기록 (Phase 2)

* **US-8:** 일반 사용자로서, 게시물을 검색할 수 있다. 그래서 특정 주제의 게시물을 찾을 수 있다.
    * *Acceptance Criteria:*
        * 목록 페이지에 검색 입력창 제공
        * 제목, 내용, 작성자로 검색 가능 (debounce 300ms)
        * 검색 결과는 목록에 실시간 반영
        * 검색 조건 초기화 버튼 제공

* **US-9:** 관리자로서, 공지사항 통계를 조회할 수 있다. 그래서 게시판 활동 현황을 파악할 수 있다.
    * *Acceptance Criteria:*
        * 게시판 유형별 게시물 수 표시
        * 최근 7일 게시물 수 추이 차트 (선택, Phase 2)
        * 상위 조회수 게시물 TOP 5 표시
        * 활동성 있는 사용자 순위 (댓글 작성 수 기반)

## 4. Scope

### 4.1 In-Scope

* **Notice (게시물) Entity**
    - 기본 정보: 제목(title), 내용(content), 게시판 유형(type: 공지/공유/지시/건의/자유)
    - 메타데이터: 작성자(author_id FK), 작성일(created_at), 수정자(updated_by_id FK, nullable), 수정일(updated_at), 조회수(view_count)
    - 메타데이터: 소프트 삭제(deleted_at), 삭제 이유(deletion_reason, nullable)
    - Unique constraint 없음 (동일 제목 중복 허용)

* **NoticeAttachment (게시물 첨부파일) Entity**
    - 게시물 FK, 파일명(filename), 파일 경로(file_path), 파일 크기(file_size), MIME 타입(mime_type)
    - 메타데이터: 업로드일(uploaded_at), 소프트 삭제(deleted_at)

* **Comment (댓글) Entity**
    - 게시물 FK, 내용(content), 작성자(author_id FK)
    - 메타데이터: 작성일(created_at), 수정일(updated_at), 소프트 삭제(deleted_at)
    - 부모 댓글 FK (parent_comment_id, nullable, 답글용)
    - 최대 깊이: 2단계 (댓글 → 답글), 답글의 답글은 불가

* **API Route Handlers (12개)**
    - Notice: GET (list, detail), POST (create), PUT (update), DELETE (soft delete)
    - Attachment: GET (download), DELETE (soft delete)
    - Comment: GET (list by notice), POST (create), PUT (update), DELETE (soft delete)
    - Statistics: GET (notice count, popular posts, user activity)

* **Frontend Pages & Components**
    - 공지사항 목록 페이지 (`/notices`)
    - 게시물 상세 페이지 (`/notices/[id]`)
    - 게시물 작성 페이지 (`/notices/new`)
    - NoticeList 컴포넌트 (게시물 테이블, 필터, 검색)
    - NoticeForm 컴포넌트 (작성/수정 폼)
    - NoticeDetail 컴포넌트 (상세 정보 + 댓글)
    - CommentSection 컴포넌트 (댓글 목록 + 작성 폼)
    - NoticeStatistics 컴포넌트 (통계 대시보드, Phase 2)

* **TanStack Query Hooks**
    - `useNotices()` — 목록 조회 (유형별, 검색 포함)
    - `useNotice(id)` — 상세 조회
    - `useCreateNotice()` — 신규 작성 mutation
    - `useUpdateNotice(id)` — 수정 mutation
    - `useDeleteNotice(id)` — 삭제 mutation
    - `useComments(noticeId)` — 댓글 목록 조회
    - `useCreateComment(noticeId)` — 댓글 작성 mutation
    - `useUpdateComment(commentId)` — 댓글 수정 mutation
    - `useDeleteComment(commentId)` — 댓글 삭제 mutation
    - `useNoticeStatistics()` — 통계 조회 (Phase 2)

* **역할 기반 접근 제어 (RBAC)**
    - USER: 조회 및 댓글/답글 작성만 가능
    - MANAGER: USER 권한 + 게시물 작성/수정/삭제 (자신의 게시물만)
    - ADMIN: 전체 게시물/댓글 조회/삭제 가능, 통계 조회 가능

* **유효성 검증**
    - 제목: 필수, 5~200자
    - 내용: 필수, 최소 10자
    - 게시판 유형: 필수, enum (공지/공유/지시/건의/자유)
    - 파일: 최대 5개, 각 10MB (이미지, PDF, 문서만)
    - 댓글: 필수, 최소 1자, 최대 1000자

* **검색 및 필터링**
    - 게시판 유형으로 필터링 (탭 또는 드롭다운)
    - 작성 날짜 범위 (선택)
    - 작성자 필터 (선택)
    - 제목/내용 검색 (실시간 debounce)
    - 정렬: 최신순, 조회수순, 댓글순, 인기도순

* **조회수 추적**
    - 게시물 상세 조회 시 조회수 +1 증가
    - 같은 사용자 반복 조회는 카운트 (과도한 조작 방지, Phase 2)

* **캐시 무효화 전략**
    - 게시물 추가/수정/삭제 시: notices-list, notices-statistics 캐시 무효화
    - 댓글 추가/수정/삭제 시: notices-detail (comments 섹션) 캐시 무효화
    - 조회수 업데이트는 캐시 무효화 미포함 (실시간 카운트)

* **Unit Testing**
    - API Route 테스트 (CRUD, 권한 검증)
    - Comment 계층 검증 테스트 (최대 2단계)
    - 파일 업로드/다운로드 테스트

## 5. Technical Considerations & Architecture Alignment

### 5.1 Next.js App Router Structure

* **Page Routes:**
    - `src/app/(main)/notices/page.tsx` — 게시물 목록 페이지 (서버 컴포넌트)
    - `src/app/(main)/notices/new/page.tsx` — 게시물 신규 작성 페이지
    - `src/app/(main)/notices/[id]/page.tsx` — 게시물 상세 페이지
    - `src/app/(main)/notices/[id]/loading.tsx` — 상세 페이지 로딩 스켈레톤

* **Layout:**
    - 공통 `src/app/(main)/layout.tsx` 사용 (사이드바, 헤더 포함)

* **Server vs Client Components:**
    - **Page:** Server Component (권한 검증, 초기 데이터 로딩)
    - **Form/Dialog:** Client Component (`'use client'` 지시어)
    - **List/Table:** Client Component (필터, 정렬, 페이지네이션)

### 5.2 API Route Handlers

| Method | Path | 설명 | 권한 |
|--------|------|------|------|
| GET | `/api/notices` | 목록 조회 (query: page, limit, type, search) | USER |
| POST | `/api/notices` | 신규 게시물 작성 | MANAGER |
| GET | `/api/notices/[id]` | 게시물 상세 조회 + 조회수 증가 | USER |
| PUT | `/api/notices/[id]` | 게시물 수정 (자신의 게시물만) | MANAGER |
| DELETE | `/api/notices/[id]` | 게시물 삭제 (ADMIN만 또는 자신의 게시물) | MANAGER/ADMIN |
| GET | `/api/notices/[id]/comments` | 댓글 목록 조회 (페이지네이션) | USER |
| POST | `/api/notices/[id]/comments` | 댓글 작성 | USER |
| PUT | `/api/notices/[id]/comments/[commentId]` | 댓글 수정 (자신의 댓글만) | USER |
| DELETE | `/api/notices/[id]/comments/[commentId]` | 댓글 삭제 (자신 또는 ADMIN) | USER |
| GET | `/api/notices/[id]/attachments/[attachmentId]/download` | 첨부파일 다운로드 | USER |
| DELETE | `/api/notices/[id]/attachments/[attachmentId]` | 첨부파일 삭제 (ADMIN 또는 게시물 작성자) | MANAGER |
| GET | `/api/notices/statistics` | 공지사항 통계 | ADMIN |

**Query Parameters (GET /api/notices):**
```
page: number (default: 1, 1-indexed)
limit: number (default: 20, max: 100)
type: string (공지 | 공유 | 지시 | 건의 | 자유 | all, default: all)
search: string (제목 또는 내용 검색)
sortBy: "latest" | "viewCount" | "commentCount" (default: latest)
startDate: string (ISO date, optional)
endDate: string (ISO date, optional)
authorId: number (optional)
```

### 5.3 Database (Oracle XE 21c + TypeORM)

**Entity 정의:**

```
NOTICE (게시물)
├── id (PK)
├── title (VARCHAR2, 최대 200자)
├── content (CLOB)
├── type (VARCHAR2: 공지 | 공유 | 지시 | 건의 | 자유)
├── author_id (FK → EMPLOYEE, ON DELETE RESTRICT)
├── view_count (NUMBER, default: 0)
├── created_at (TIMESTAMP)
├── updated_at (TIMESTAMP)
├── updated_by_id (FK → EMPLOYEE, nullable, ON DELETE SET NULL)
├── deleted_at (TIMESTAMP, soft delete)
├── deletion_reason (VARCHAR2, nullable)
└── Indexes:
    ├── PRIMARY KEY (id)
    ├── (type)
    ├── (created_at)
    ├── (author_id)
    ├── (deleted_at)
    ├── (view_count DESC) — 조회수순 정렬 성능

NOTICE_ATTACHMENT (첨부파일)
├── id (PK)
├── notice_id (FK → NOTICE, ON DELETE RESTRICT)
├── filename (VARCHAR2)
├── file_path (VARCHAR2)
├── file_size (NUMBER)
├── mime_type (VARCHAR2)
├── uploaded_at (TIMESTAMP)
├── deleted_at (TIMESTAMP, soft delete)
└── Indexes:
    ├── PRIMARY KEY (id)
    ├── (notice_id)

COMMENT (댓글)
├── id (PK)
├── notice_id (FK → NOTICE, ON DELETE RESTRICT)
├── content (VARCHAR2, 최대 1000자)
├── author_id (FK → EMPLOYEE, ON DELETE RESTRICT)
├── parent_comment_id (FK → COMMENT, nullable, ON DELETE RESTRICT, 답글용)
├── created_at (TIMESTAMP)
├── updated_at (TIMESTAMP)
├── deleted_at (TIMESTAMP, soft delete)
└── Indexes:
    ├── PRIMARY KEY (id)
    ├── (notice_id)
    ├── (author_id)
    ├── (parent_comment_id)
    ├── (created_at)
```

**Constraints:**
- `ON DELETE RESTRICT` for author_id, notice_id (audit trail)
- `ON DELETE SET NULL` for updated_by_id (optional update tracking)
- Check constraint on NOTICE.type (enum values only)
- Comment depth constraint: parent_comment_id의 parent_comment_id는 NULL이어야 함 (max 2 levels)

### 5.4 State Management

* **Server State (TanStack Query):**
    - `notices-list`: 목록 조회 캐시 (staleTime: 5분, gcTime: 30분)
    - `notices-detail-{id}`: 상세 조회 캐시 (staleTime: 10분, gcTime: 30분)
    - `notices-comments-{id}`: 댓글 목록 캐시 (staleTime: 3분, gcTime: 15분)
    - `notices-statistics`: 통계 캐시 (staleTime: 30분, gcTime: 60분)

* **Client State (Zustand, 선택):**
    - 목록 페이지 필터 상태 (게시판 유형, 검색 입력, 정렬) — localStorage persist

* **Form State (React Hook Form):**
    - 게시물 작성/수정, 댓글 작성 폼 상태

### 5.5 Authentication & Authorization

* **NextAuth.js:** Session 객체에 `user.role`, `user.id` 포함
* **Page-level:** 각 페이지 Server Component에서 세션 검증 (USER 이상 필수)
* **API-level:** 각 Route Handler에서 권한 검증
    - GET: USER 이상
    - POST (게시물): MANAGER 이상
    - PUT/DELETE (게시물): 자신의 게시물 또는 ADMIN
    - POST (댓글): USER 이상
    - PUT/DELETE (댓글): 자신의 댓글 또는 ADMIN
* **Middleware:** `src/middleware.ts`에서 `/notices` 경로 보호

### 5.6 파일 업로드 및 다운로드

* **업로드 경로:** `./public/uploads/notices/{noticeId}/{filename}`
* **파일 제한:**
    - 최대 5개 파일
    - 각 파일 최대 10MB
    - MIME 타입: image/*, application/pdf, application/msword, application/vnd.openxmlformats-officedocument*
* **보안:**
    - 파일명 sanitization (special character 제거)
    - UUID 기반 파일명 생성 (원본 파일명은 DB에만 저장)
    - 다운로드 시 권한 검증 (로그인 사용자만)

### 5.7 입력 검증 및 보안

* **Server-side 검증 (필수):**
    - 제목: 필수, 5~200자, XSS 방지
    - 내용: 필수, 최소 10자, XSS 방지
    - 댓글: 필수, 최소 1자, 최대 1000자, XSS 방지
    - 게시판 유형: enum 검증
    - 파일: MIME 타입, 크기 검증

* **Client-side 검증:**
    - React Hook Form으로 실시간 피드백

* **XSS 방지:**
    - 댓글 내용 sanitization (DOMPurify 또는 유사)
    - 게시물 내용은 WYSIWYG 에디터의 safe mode 사용

* **CSRF 방지:**
    - NextAuth.js 자동 처리

### 5.8 성능 최적화

* **API Response Time Target:** p95 < 200ms
* **Pagination:** 기본 20개, 최대 100개
* **Index Strategy:**
    - `NOTICE(type, created_at)` — 유형별 + 날짜 필터링
    - `NOTICE(view_count DESC)` — 조회수순 정렬
    - `COMMENT(notice_id, created_at)` — 게시물별 댓글 조회
    - `NOTICE_ATTACHMENT(notice_id)` — 첨부파일 조회

* **Lazy Loading:**
    - 첨부파일은 상세 페이지에서만 로드
    - 댓글은 별도 쿼리 (list에 포함 안 함)

* **조회수 업데이트:**
    - 비동기 업데이트 (응답 지연 없음)
    - 중복 조회 방지 (세션별 쿠키 또는 DB 기반, Phase 2)

## 8. Security Considerations

* **Authentication:** NextAuth.js session 기반, 모든 API 호출 전 세션 검증
* **Authorization:**
    - USER: 조회, 댓글/답글 작성만
    - MANAGER: USER 권한 + 게시물 작성/수정/삭제 (자신의 게시물만)
    - ADMIN: 모든 권한
    - API 레벨에서 권한 검증 (프론트엔드 숨김만으로 불충분)

* **XSS 방지:**
    - 댓글 내용 sanitization (DOMPurify)
    - 게시물 제목/내용은 WYSIWYG 에디터의 safe mode 사용

* **File Security:**
    - MIME 타입 검증 (whitelist)
    - 파일 크기 제한 (각 10MB, 총 5개)
    - 파일 저장 경로 격리 (public/uploads/notices/)
    - 다운로드 시 권한 검증

* **Input Validation:**
    - Server-side 검증 필수 (모든 입력값)
    - SQL Injection 방지: TypeORM parameterized queries
    - CSRF 방지: NextAuth.js 자동 처리

* **Data Protection:**
    - 게시물 및 댓글은 민감 정보 취급
    - 작성자 정보는 표시 (감사 추적)
