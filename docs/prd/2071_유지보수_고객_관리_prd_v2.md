## 1. Overview

본 PRD는 sunjin-erp 시스템의 "유지보수 고객 관리" 기능에 대한 요구사항을 정의한다.
이 기능은 유지보수 계약이 체결된 고객사의 계약 정보, 담당 영업 사원 할당, 유지보수 계약서 파일 관리를 통해 계약 생명주기를 효율적으로 관리하는 시스템을 구축한다.

**대상 모듈:** 유지보수 고객 관리 (Maintenance Customer Management)
**대상 사용자 역할:** USER / MANAGER / ADMIN
**주요 기능:** 유지보수 계약 조회/생성/수정/상태관리, 계약서 파일 첨부, 담당자 배정, 계약 이력 추적

---

## 2. Goals & Objectives

*   **계약 생명주기 관리:** 유지보수 계약 체결부터 만료까지의 전체 라이프사이클을 관리하여 계약 현황을 명확히 한다.
*   **담당자 할당 관리:** 계약별 영업 담당자를 명확하게 지정하여 책임 소재를 명확히 하고 커뮤니케이션을 원활하게 한다.
*   **계약서 문서 관리:** 계약서(PDF, Word 등) 파일을 중앙 집중식으로 관리하여 필요 시 신속한 문서 검색 및 조회를 가능하게 한다.
*   **계약 현황 시각화:** 계약 상태(활성/종료/갱신예정) 기반으로 한눈에 계약 현황을 파악할 수 있도록 대시보드 제공.
*   **계약 갱신 추적:** 계약 종료일 임박 알림, 갱신 이력 기록으로 계약 중단 방지 및 사업 기회 확보.

## 3. User Stories / Use Cases

*   **User Story 1: 유지보수 계약 목록 조회**
    - **역할:** USER / MANAGER / ADMIN
    - **설명:** 사용자로서, 현재 체결된 유지보수 계약 목록을 조회하고 싶다. 그래서 어떤 고객사와 계약이 진행 중인지 파악할 수 있다.
    - *Acceptance Criteria:*
        - 계약 목록 페이지에서 모든 활성 유지보수 계약이 테이블 형식으로 표시된다
        - 각 행에 고객사명, 계약명, 계약 기간(시작/종료), 담당 영업자, 계약 상태가 표시된다
        - 기본 정렬: 계약 종료일(임박순)
        - **페이지네이션: 기본 20개 항목/페이지, 최대 50개 항목/페이지 (REVISED FROM 100)**

*   **User Story 2: 필터링 및 검색**
    - **역할:** USER / MANAGER / ADMIN
    - **설명:** 사용자로서, 특정 고객사의 계약만 필터링하거나 계약명으로 검색하고 싶다. 그래서 원하는 계약을 빠르게 찾을 수 있다.
    - *Acceptance Criteria:*
        - 필터 조건: 계약 상태(활성/종료/갱신예정), 담당자(단일), 고객사(검색), 계약 기간(범위)
        - 검색: 계약명, 고객사명 (부분 검색, 대소문자 무시)
        - **필터 적용 시 URL query parameter 업데이트 (TanStack Query 관리)**
        - 필터 리셋: "초기화" 버튼으로 모든 필터 제거 + 기본값 복원
        - **Query Parameter 형식**: `?status=ACTIVE&assignedEmployeeId=5&endDateFrom=2026-01-01&endDateTo=2026-12-31&page=1&limit=20`

*   **User Story 3: 계약 상세 조회**
    - **역할:** USER / MANAGER / ADMIN
    - **설명:** 사용자로서, 특정 계약의 상세 정보(계약 조건, 담당자, 첨부 문서)를 확인하고 싶다. 그래서 계약의 모든 세부사항을 파악할 수 있다.
    - *Acceptance Criteria:*
        - 계약 상세 페이지: 기본 정보 + 첨부 문서 + 갱신 이력
        - 기본 정보: ID, 고객사명, 계약명, 계약 기간(시작/종료), 계약 금액, 계약 상태, 담당 영업자, 계약 유형
        - **첨부 문서: 계약서 파일 목록 (페이지네이션: 10개/페이지)**
        - **갱신 이력: 과거 계약 갱신 기록 (페이지네이션: 20개/페이지)**

*   **User Story 4: 유지보수 계약 신규 생성**
    - **역할:** MANAGER / ADMIN
    - **설명:** MANAGER/ADMIN으로서, 신규 유지보수 계약을 시스템에 등록하고 싶다. 그래서 새로운 고객사와의 계약을 관리 대상으로 추가할 수 있다.
    - *Acceptance Criteria:*
        - 신규 계약 폼: 고객사(선택/검색), 계약명, 시작일, 종료일, 계약 금액(선택), 담당 영업자, 계약 유형, 비고(선택)
        - 필드 검증: 고객사/계약명/기간/담당자 필수, 시작일 ≤ 종료일
        - 제출 후: 상태 자동 설정 "활성", 계약 생성 이력 자동 기록
        - 성공 메시지 + 상세 페이지로 자동 이동

*   **User Story 5: 계약 정보 수정**
    - **역할:** MANAGER / ADMIN
    - **설명:** MANAGER/ADMIN으로서, 기존 계약의 정보(담당자, 기간, 금액)를 수정하고 싶다. 그래서 변경된 계약 정보를 반영할 수 있다.
    - *Acceptance Criteria:*
        - 수정 폼: 계약명, 기간, 금액, 담당자, 유형 수정 가능
        - 고객사명은 수정 불가 (생성 후 고정)
        - 상태 변경: "활성" ↔ "종료", "갱신예정"으로 수정 가능
        - 변경사항 저장 시 업데이트 이력 자동 기록

*   **User Story 6: 계약서 파일 첨부**
    - **역할:** MANAGER / ADMIN
    - **설명:** MANAGER/ADMIN으로서, 유지보수 계약서(PDF, Word) 파일을 계약에 첨부하고 싶다. 그래서 계약 문서를 중앙에서 관리할 수 있다.
    - *Acceptance Criteria:*
        - 파일 업로드: 계약 상세 페이지에서 "파일 추가" 버튼으로 업로드
        - 허용 파일: PDF, DOCX, DOC (최대 10MB, **파일당 5개 한정, 중복 허용**)
        - 업로드 시: 파일명, 업로드자, 업로드 날짜 자동 기록
        - 첨부 파일 목록: 다운로드, 삭제(ADMIN만) 가능
        - **중복 파일 정책: 같은 이름 파일 여러 개 업로드 가능 (UUID 기반, MANAGER가 관리)**

*   **User Story 7: 계약 상태 관리**
    - **역할:** MANAGER / ADMIN
    - **설명:** MANAGER/ADMIN으로서, 계약의 상태를 변경(활성/종료/갱신예정)하고 싶다. 그래서 계약 라이프사이클을 명확히 관리할 수 있다.
    - *Acceptance Criteria:*
        - **상태 전이 (모두 수동, MANAGER 주도)**:
            - 활성 → 종료 (계약 만료 시)
            - 활성 → 갱신예정 (MANAGER가 수동으로 설정, 약 3개월 전)
            - 갱신예정 → 활성 (갱신 완료 시)
            - 종료 → 활성 (재계약 시)
        - **자동 상태 전이 없음: 모든 상태 변경은 MANAGER가 명시적으로 UI를 통해 수행**
        - 상태 변경 시: 사유 필수 기입, 변경자/변경일 자동 기록

*   **User Story 8: 계약 만료 알림**
    - **역할:** MANAGER / ADMIN
    - **설명:** MANAGER/ADMIN으로서, 계약 만료 예정인 계약을 시각적으로 식별하고 싶다. 그래서 갱신 기한을 놓치지 않을 수 있다.
    - *Acceptance Criteria:*
        - 목록 페이지에서 30일 내 종료 예정 계약은 경고 배지(Red) 표시
        - 60일 내 종료 예정 계약은 주의 배지(Yellow) 표시
        - 상세 페이지에서 남은 기간 카운트다운 표시
        - 필터: "30일 내 만료" 등의 빠른 필터 제공

*   **User Story 9: 계약 갱신 이력**
    - **역할:** MANAGER / ADMIN
    - **설명:** MANAGER/ADMIN으로서, 과거 계약 갱신 이력을 조회하고 싶다. 그래서 계약의 역사와 현황을 파악할 수 있다.
    - *Acceptance Criteria:*
        - 상세 페이지 "갱신 이력" 탭에서 과거 갱신 기록 표시
        - **갱신은 MANAGER가 end_date를 업데이트하면 자동으로 이력 기록됨**
        - 각 이력: 이전 종료일, 새로운 종료일, 갱신일, 갱신자, 비고
        - 시간순 정렬 (최신순)

*   **User Story 10: 계약 삭제 (소프트 삭제)**
    - **역할:** ADMIN만
    - **설명:** ADMIN으로서, 더 이상 관리하지 않는 계약을 삭제하고 싶다. 그래서 불필요한 정보를 제거할 수 있다.
    - *Acceptance Criteria:*
        - 삭제 버튼: ADMIN만 표시
        - 삭제 시: 확인 다이얼로그 표시 (실수 방지)
        - **소프트 삭제: 계약 + 모든 첨부 + 모든 이력을 deleted_at 설정하여 삭제**
        - 삭제 이력 자동 기록

## 4. Scope

### 4.1 In-Scope

*   유지보수 계약 목록 조회 (필터링, 검색, 정렬, 페이지네이션)
*   계약 상세 조회 (기본 정보 + 첨부 문서 + 갱신 이력, 중첩 리소스 페이지네이션)
*   유지보수 계약 신규 생성
*   계약 정보 수정
*   **계약 상태 변경 (활성/종료/갱신예정) - MANAGER 수동 주도, 자동 전이 없음**
*   계약서 파일 첨부 (PDF, DOCX, DOC, 최대 5개, 중복 허용)
*   첨부 파일 다운로드/삭제 (ADMIN만)
*   계약 갱신 이력 조회 (수동 갱신, 자동 이력 기록)
*   계약 만료 알림 (30일/60일 경고 배지)
*   소프트 삭제 (ADMIN만, 계약 + 첨부 + 이력 함께 삭제)
*   권한 기반 접근 제어 (USER: 조회만, MANAGER: CRUD, ADMIN: 전체, Phase 1: 오픈 액세스)
*   고객사 정보와의 연계 (Customer 테이블)
*   영업 담당자 정보 연계 (Employee 테이블)

### 4.2 Out-of-Scope

*   **계약 자동 상태 전이 (Phase 2)**: 시스템이 3개월 전에 자동으로 "갱신예정" 설정
*   **자동 계약 갱신 (Phase 2)**: 자동으로 새 계약 생성 및 기존 계약 종료
*   계약 금액 기반 매출 인식 (회계 모듈과 연계)
*   계약 서명/전자 서명 (별도 전자계약 시스템)
*   계약 분석 대시보드 (고급 분석)
*   다국어 지원
*   부서별 액세스 제어 (Phase 2)
*   파일 버전 관리 (Phase 2)
*   대량 작업 (Bulk delete/update) (Phase 2)

## 5. Technical Considerations & Architecture Alignment

### 5.1 Next.js App Router Structure

*   **Page Routes:**
    - `src/app/(main)/maintenance/page.tsx` — 계약 목록 페이지 (Server Component)
    - `src/app/(main)/maintenance/[id]/page.tsx` — 계약 상세 페이지 (Server Component)
    - `src/app/(main)/maintenance/new/page.tsx` — 계약 등록 페이지 (Server Component + Client Form)

*   **Layout:** `src/app/(main)/layout.tsx`에서 공통 레이아웃 상속

*   **Server vs Client Components:**
    - `maintenance/page.tsx`: Server Component — 데이터 페칭, 권한 검증
    - `maintenance/[id]/page.tsx`: Server Component — 계약 + 첨부 + 이력 조회
    - 폼 컴포넌트 (`MaintenanceContractForm`, `StatusChangeForm` 등): Client Component — 폼 상태, 유효성 검증

### 5.2 API Route Handlers

*   `GET /api/maintenance` — 유지보수 계약 목록 조회 (필터, 정렬, 페이지네이션)
    - Query Parameters: `status`, `assignedEmployeeId`, `customerId`, `contractNameSearch`, `startDateFrom`, `startDateTo`, `endDateFrom`, `endDateTo`, `sort`, `page`, `limit`
*   `POST /api/maintenance` — 신규 계약 생성
*   `GET /api/maintenance/[id]` — 계약 상세 조회 (첨부/이력 첫 페이지)
*   `PUT /api/maintenance/[id]` — 계약 정보 수정
*   `DELETE /api/maintenance/[id]` — 소프트 삭제 (ADMIN만, 계약+첨부+이력)
*   `POST /api/maintenance/[id]/status` — 계약 상태 변경 (수동)
*   `POST /api/maintenance/[id]/attachments` — 계약서 파일 업로드
*   `GET /api/maintenance/[id]/attachments` — 파일 목록 조회 (페이지네이션: 10/page)
*   `DELETE /api/maintenance/[id]/attachments/[attachmentId]` — 파일 삭제 (ADMIN만)
*   `GET /api/maintenance/[id]/attachments/[attachmentId]/download` — 파일 다운로드
*   `GET /api/maintenance/[id]/history` — 갱신 이력 조회 (페이지네이션: 20/page)
*   `GET /api/maintenance/stats` — 계약 통계 (상태별 집계)

### 5.3 Database (Oracle XE 21c + TypeORM)

#### 쿼리 최적화 인덱스

```sql
-- 선택적 인덱스 (deleted_at IS NULL 조건 포함)
CREATE INDEX idx_mc_customer_active
  ON MaintenanceContract(customer_id)
  WHERE deleted_at IS NULL;

CREATE INDEX idx_mc_employee_active
```

### 5.5 Authentication & Authorization

*   **NextAuth.js:** Session 기반 인증
*   **권한 검증 (Defense in Depth):**

| 엔드포인트 | GET | POST | PUT | DELETE | 비고 |
|-----------|-----|------|-----|--------|------|
| /api/maintenance | USER+ | MANAGER+ | - | - | 목록 조회/생성 |
| /api/maintenance/[id] | USER+ | - | MANAGER+ | ADMIN | 상세/수정/삭제 |
| /api/maintenance/[id]/status | - | - | MANAGER+ | - | 상태변경 |
| /api/maintenance/[id]/attachments | USER+ | MANAGER+ | - | ADMIN | 파일 조회/업로드 |
| /api/maintenance/[id]/history | USER+ | - | - | - | 이력 조회 (읽기만) |
| /api/maintenance/stats | USER+ | - | - | - | 통계 (읽기만) |

*   **Authorization 적용:**
    - **Layer 1 (Server Component):** 페이지 접근 권한 검증, 미인증 시 redirect
    - **Layer 2 (API Route):** 역할 검증, 미달 시 401/403 반환
    - **Layer 3 (UI Component):** 버튼 비활성화, "ADMIN 권한 필요" 메시지
    - **Policy (Phase 1):** All MANAGERs can access all contracts (no row-level access control yet)

*   **각 API Route 예시:**
```typescript
export async function PUT(req, { params }) {
  const session = await getServerSession();

  // 1. 인증 확인
  if (!session?.user) {
    return Response.json({ error: 'Unauthorized' }, { status: 401 });
  }

  // 2. 역할 확인 (MANAGER+)
  if (!['MANAGER', 'ADMIN'].includes(session.user.role)) {
    return Response.json({ error: 'Forbidden' }, { status: 403 });
  }

  // 3. 리소스 확인
  const contract = await getContract(params.id);
  if (!contract) {
    return Response.json({ error: 'Not found' }, { status: 404 });
  }

  // 4. 권한 기반 작업 수행
  const updated = await updateContract(params.id, req.body);
  return Response.json(updated);
}
```

## 8. Security Considerations

*   **Authentication:** 모든 API route에서 `getServerSession()` 검증, 미인증 시 401 반환
*   **Authorization:** Role-based access control (Defense in Depth)
    - Layer 1 (Server Component): 페이지 접근 권한
    - Layer 2 (API Route): 엔드포인트 역할 검증
    - Layer 3 (UI): 버튼 비활성화 및 권한 표시
*   **Input Validation:** 서버사이드 필수
    - 계약명: 길이 제약 (1-255자)
    - 날짜: 유효한 날짜 형식, start_date ≤ end_date
    - 금액: 숫자 형식, 양수 (nullable)
    - 파일: MIME 타입 검증 (PDF, DOCX, DOC), 크기 제약 (10MB)
*   **SQL Injection 방지:** TypeORM parameterized queries 사용
*   **XSS 방지:** React 자동 escaping, 사용자 입력은 항상 sanitize
*   **File Upload Security:**
    - 파일 확장자 화이트리스트 (.pdf, .docx, .doc)
    - MIME 타입 검증 (매직 바이트 확인)
    - 저장 경로: 공개 폴더 외부 (`/uploads/maintenance/`)
    - 파일명: UUID + 원본 파일명으로 저장 (경로 탈출 방지)
    - 다운로드: `Content-Disposition: attachment` (브라우저 열기 방지, XSS 방지)
*   **Data Protection:** 민감 정보 없음 (계약 정보는 내부용)
*   **Soft Delete:** 물리 삭제 금지, `deleted_at` 필터로 논리 삭제
    - **Repository Pattern 강제:** 모든 쿼리에서 deleted_at IS NULL 필터 필수
    - 계약 삭제 시: 계약 + 첨부 + 이력 함께 soft-delete (단일 트랜잭션)
