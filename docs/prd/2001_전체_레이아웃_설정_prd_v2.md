# Product Requirement Document: 전체 레이아웃 설정 (v2)

문서번호: 2001
작성일: 2026-01-24
상위문서: 1000_초안.prd
버전: v2 (Review Pipeline 결과 반영)

## 1. Overview

본 PRD는 sunjin-erp 시스템의 "전체 레이아웃 설정" 기능에 대한 요구사항을 정의한다.
이 기능은 모든 페이지의 공통 UI 구조(사이드바, 헤더, 콘텐츠 영역)를 정의하고, 인증 상태에 따른 레이아웃 분기와 역할 기반 네비게이션을 제공하는 애플리케이션 쉘(App Shell)을 구축한다.

**대상 모듈:** 공통 레이아웃 (전체 시스템)
**대상 사용자 역할:** ADMIN / MANAGER / USER

## 2. Goals & Objectives

* **일관된 UI 구조 제공:** 모든 인증된 페이지에서 동일한 사이드바 + 헤더 + 콘텐츠 레이아웃을 유지한다.
* **인증 상태별 레이아웃 분기:** 비인증 사용자는 로그인 전용 레이아웃, 인증 사용자는 메인 레이아웃을 표시한다.
* **역할 기반 네비게이션:** 사용자 권한(ADMIN/MANAGER/USER)에 따라 접근 가능한 메뉴를 동적으로 제어한다.
* **반응형 지원:** Desktop(1280px+) 우선 설계, Tablet(768px+) 지원, 사이드바 축소/확장 가능.
* **빠른 네비게이션:** 클라이언트 사이드 라우팅으로 페이지 전환 시 레이아웃 리렌더링 없이 콘텐츠만 교체한다.

## 3. User Stories / Use Cases

* **US-1:** 인증된 사용자로서, 로그인 후 사이드바와 헤더가 있는 메인 레이아웃을 볼 수 있다. 그래서 각 모듈에 빠르게 접근할 수 있다.
    * *Acceptance Criteria:*
        * 로그인 성공 시 대시보드 페이지로 이동하며 사이드바 + 헤더가 표시된다
        * 사이드바에 10개 모듈 메뉴가 그룹별로 표시된다
        * 현재 활성 메뉴가 시각적으로 구분된다

* **US-2:** 비인증 사용자로서, 로그인 페이지에서는 사이드바/헤더 없이 로그인 폼만 표시된다.
    * *Acceptance Criteria:*
        * 인증되지 않은 상태에서 모든 (main) 경로 접근 시 로그인 페이지로 리다이렉트된다
        * 로그인 페이지는 중앙 정렬된 단일 카드 레이아웃이다

* **US-3:** 사용자로서, 사이드바를 축소(collapse)하여 콘텐츠 영역을 넓게 사용할 수 있다.
    * *Acceptance Criteria:*
        * 사이드바 토글 버튼(하단) 또는 키보드 단축키(`Ctrl/Cmd+B`)로 축소/확장 전환 가능
        * 축소 시 아이콘만 표시, 확장 시 아이콘 + 텍스트 표시
        * 축소/확장 상태가 localStorage에 유지된다 (새로고침 후에도 유지)

* **US-4:** ADMIN 역할 사용자로서, 직원 관리 메뉴를 볼 수 있다. MANAGER는 읽기 전용으로, 일반 USER는 해당 메뉴가 표시되지 않는다.
    * *Acceptance Criteria:*
        * ADMIN: 전체 메뉴 접근 가능 (CRUD)
        * MANAGER: 직원 관리 메뉴 표시, 부서 내 읽기 전용 (수정/삭제 비활성화)
        * USER: 직원 관리 메뉴 미표시

* **US-5:** 사용자로서, 헤더에서 본인의 이름, 역할을 확인하고 로그아웃할 수 있다.
    * *Acceptance Criteria:*
        * 헤더 우측에 사용자 이름 및 역할 배지 표시
        * 프로필 드롭다운 메뉴에서 로그아웃 가능
        * 로그아웃 시 세션 종료 후 로그인 페이지로 이동

* **US-6:** Tablet 환경의 사용자로서, 사이드바가 오버레이 형태로 열리고 콘텐츠 영역을 가리지 않는다.
    * *Acceptance Criteria:*
        * 768px 미만에서 사이드바는 기본 숨김 상태
        * 햄버거 메뉴 클릭 시 오버레이로 사이드바 표시
        * 메뉴 선택 또는 외부 클릭 시 사이드바 자동 닫힘

* **US-7:** 사용자로서, Breadcrumb을 통해 현재 위치를 확인하고 상위 페이지로 이동할 수 있다.
    * *Acceptance Criteria:*
        * 헤더 하단 또는 콘텐츠 상단에 Breadcrumb 표시
        * 정적 경로: 설정 파일 기반 레이블 매핑 (예: "/customers" → "고객 관리")
        * 동적 경로: resolver로 실제 이름 표시 (예: "/customers/123" → "고객 관리 > 삼성전자")
        * 각 Breadcrumb 항목 클릭 시 해당 경로로 이동

* **US-8:** 사용자로서, 페이지 전환 시 스켈레톤 UI가 표시되어 로딩 상태를 인지할 수 있다.
    * *Acceptance Criteria:*
        * 페이지 전환 시 사이드바/헤더는 유지, 콘텐츠 영역만 스켈레톤 UI로 대체
        * `(main)/loading.tsx`에 기본 스켈레톤 정의
        * 각 모듈에서 필요 시 모듈별 `loading.tsx`로 재정의 가능

## 4. Scope

### 4.1 In-Scope

* Next.js App Router Route Group 레이아웃 구조 (`(auth)`, `(main)`)
* **Server Component + Client Shell 패턴** 적용 (layout.tsx는 SC, MainShell은 CC)
* 사이드바 네비게이션 컴포넌트 (축소/확장, 역할 기반 필터링, 그룹핑)
* 헤더 컴포넌트 (사용자 정보, 로그아웃, 사이드바 토글)
* 메인 콘텐츠 영역 레이아웃 (스크롤, 패딩, 기본 max-w-full)
* Breadcrumb 네비게이션 (라우트 설정 + 동적 resolver)
* 반응형 디자인 (Desktop / Tablet)
* 사이드바 상태 영속성 (localStorage)
* 인증 상태 기반 리다이렉트 (middleware)
* 키보드 단축키 (`Ctrl/Cmd+B` 사이드바 토글)
* 페이지 전환 로딩 UI (공통 스켈레톤)
* 사이드바 하단 영역 (버전 정보 + 토글 버튼)
* TanStack Query global onError에서 401 응답 시 로그인 리다이렉트

### 4.2 Out-of-Scope

* 각 모듈의 실제 페이지 콘텐츠 구현
* 알림(Notification) 시스템
* 다국어(i18n) 지원
* 다크 모드 / 테마 전환
* 모바일(< 768px) 전용 레이아웃
* 세션 갱신 전략, 폼 임시 저장 등 상세 세션 관리 (별도 Auth PRD)
* Lighthouse CI 자동화 (안정화 후 도입)

## 5. Technical Considerations & Architecture Alignment

### 5.1 Next.js App Router Structure

* **Route Groups:**
    - `src/app/(auth)/layout.tsx` — 인증 전 레이아웃 (로그인 전용, 사이드바/헤더 없음)
    - `src/app/(auth)/login/page.tsx` — 로그인 페이지
    - `src/app/(main)/layout.tsx` — **Server Component**. 세션 조회 후 `<MainShell>` 렌더링
    - `src/app/(main)/loading.tsx` — 공통 스켈레톤 UI (콘텐츠 영역)
    - `src/app/(main)/dashboard/page.tsx` — 기본 랜딩 페이지

* **Server/Client Component 분리:**
    ```tsx
    // src/app/(main)/layout.tsx (Server Component)
    import { getServerSession } from 'next-auth';
    import { MainShell } from '@/components/layout/MainShell';

    export default async function MainLayout({ children }) {
      const session = await getServerSession(authOptions);
      return <MainShell session={session}>{children}</MainShell>;
    }
    ```

    ```tsx
    // src/components/layout/MainShell.tsx ('use client')
    'use client';
    export function MainShell({ session, children }) {
      // Zustand store, event handlers 사용 가능
      return (
        <div className="flex h-screen">
          <Sidebar session={session} />
          <div className="flex flex-col flex-1">
            <Header session={session} />
            <main className="flex-1 overflow-y-auto p-6">
              {children}
            </main>
          </div>
        </div>
      );
    }
    ```

* **Root Layout:** `src/app/layout.tsx`
    - HTML/Body 태그, 폰트 설정, TanStack Query Provider, NextAuth SessionProvider 포함
    - Toaster (알림 토스트) 글로벌 렌더링

* **Middleware:** `src/middleware.ts`
    - NextAuth 세션 확인
    - 미인증 사용자 → `/login` 리다이렉트
    - 인증된 사용자의 `/login` 접근 → `/dashboard` 리다이렉트

### 5.2 API Route Handlers

* `GET /api/auth/session` — 현재 세션 정보 조회 (NextAuth 제공)
* `POST /api/auth/signout` — 로그아웃 처리 (NextAuth 제공)

### 5.3 Database (Oracle XE 21c + TypeORM)

* 레이아웃 자체는 DB 의존성 없음
* 사이드바 메뉴 구성은 정적 정의 (코드 내 상수)
* 사용자 정보(이름, 역할, 부서)는 NextAuth session에서 제공

### 5.4 State Management

* **Zustand Store:** `useSidebarStore`
    - `isCollapsed: boolean` — 사이드바 축소 상태
    - `isMobileOpen: boolean` — 모바일/태블릿 오버레이 상태
    - `toggle()` — 축소/확장 전환
    - `setMobileOpen(open: boolean)` — 모바일 사이드바 열기/닫기
    - localStorage persist middleware로 상태 유지

* **Server State:** 없음 (레이아웃은 순수 클라이언트 UI)

* **TanStack Query 설정:**
    ```tsx
    const queryClient = new QueryClient({
      defaultOptions: {
        queries: {
          retry: (failureCount, error) => {
            if (error.status === 401) return false; // 401은 재시도 안 함
            return failureCount < 3;
          },
        },
        mutations: {
          onError: (error) => {
            if (error.status === 401) {
              window.location.href = '/login';
            }
          },
        },
      },
    });
    ```

### 5.5 Authentication & Authorization

* **NextAuth.js:** Session 객체에 `user.role`, `user.name`, `user.department` 포함
* **Middleware:** `src/middleware.ts`에서 route-level 보호
* **Menu Visibility:** 사이드바 메뉴 항목별 `requiredRole` 속성으로 필터링
* **SessionProvider:** `refetchOnWindowFocus: true` 설정으로 세션 상태 동기화

### 5.7 Breadcrumb 구현 전략

* **라우트 설정 파일:** `src/lib/breadcrumb-config.ts`
    ```tsx
    export const breadcrumbMap: Record<string, string> = {
      '/dashboard': '대시보드',
      '/tasks': '업무 검색',
      '/support': '기술지원',
      '/projects': '프로젝트',
      '/issues': '장애 현황',
      '/inventory': '재고 관리',
      '/maintenance': '유지보수',
      '/customers': '고객 관리',
      '/employees': '직원 관리',
      '/notices': '공지사항',
    };
    ```

* **동적 세그먼트 resolver:**
    - 각 모듈 페이지에서 동적 세그먼트의 display name을 제공
    - Breadcrumb Context 또는 Zustand로 전달
    - 예: 고객 상세 페이지에서 `setBreadcrumbLabel('삼성전자')` 호출

* **Breadcrumb 컴포넌트:** `src/components/layout/Breadcrumb.tsx`
    - 현재 pathname을 파싱하여 설정 파일 + resolver 레이블 합성
    - shadcn/ui Breadcrumb 컴포넌트 활용

### 5.8 키보드 단축키

| 단축키 | 동작 |
|--------|------|
| `Ctrl+B` (Windows/Linux) | 사이드바 축소/확장 토글 |
| `Cmd+B` (macOS) | 사이드바 축소/확장 토글 |

* 구현: MainShell에 `useEffect`로 `keydown` 이벤트 리스너 등록
* 충돌 방지: 텍스트 입력 중(`input`, `textarea` 포커스 시) 단축키 비활성화

## 6. UI/UX Considerations

### 6.1 Component Library

* **shadcn/ui 활용 컴포넌트:**
    - `Button` — 사이드바 토글, 로그아웃
    - `Avatar` — 사용자 프로필 아이콘
    - `DropdownMenu` — 사용자 메뉴 (로그아웃, 프로필)
    - `Tooltip` — 사이드바 축소 시 메뉴명 표시
    - `Separator` — 메뉴 그룹 구분
    - `Sheet` — 모바일 사이드바 오버레이
    - `Breadcrumb` — 현재 위치 표시
    - `Skeleton` — 페이지 전환 로딩 UI

* **Lucide React Icons:** 각 메뉴별 아이콘 적용

### 6.2 레이아웃 구조

```
┌─────────────────────────────────────────────────┐
│ Header (h-14)                                    │
│  [☰ Toggle] [Breadcrumb]          [User ▾]      │
├────────┬────────────────────────────────────────┤
│        │                                         │
│ Side   │  Main Content Area                      │
│ bar    │  (p-6, max-w-full, overflow-y-auto)     │
│ (w-64  │                                         │
│  or    │  ┌─────────────────────────────────┐   │
│  w-16) │  │  Page Content (children)        │   │
│        │  │  * 폼/상세: max-w-5xl 래핑 가능  │   │
│        │  └─────────────────────────────────┘   │
│        │                                         │
│ ────── │                                         │
│ [v0.1] │                                         │
│ [◀ ▶]  │                                         │
└────────┴────────────────────────────────────────┘
```

* **사이드바 확장:** width 256px (w-64), 아이콘 + 텍스트
* **사이드바 축소:** width 64px (w-16), 아이콘만 (hover tooltip)
* **사이드바 하단:** 앱 버전 정보 + 축소/확장 토글 버튼
* **헤더 높이:** 56px (h-14), 하단 border
* **콘텐츠 영역:** 나머지 전체 높이, 내부 스크롤, **기본 max-w-full** (페이지별 제한 가능)
* **메뉴 그룹:** Separator로 시각적 구분 (그룹 레이블 없음)

### 6.3 Responsive Design

| Breakpoint | 사이드바 동작 | 헤더 동작 |
|------------|--------------|-----------|
| Desktop (1280px+) | 고정 표시, 축소/확장 가능 | 전체 표시 |
| Tablet (768px~1279px) | 기본 축소, 확장 가능 | 전체 표시 |
| Small Tablet (< 768px) | 숨김, Sheet 오버레이로 표시 | 햄버거 메뉴 표시 |

### 6.4 User Feedback

* **Active Route:** 현재 페이지에 해당하는 사이드바 메뉴 항목에 배경색 하이라이트 + 좌측 인디케이터
* **Hover Effect:** 메뉴 항목 hover 시 배경색 변화
* **Transition:** 사이드바 축소/확장 시 width transition (200ms ease)
* **Loading:** 페이지 전환 시 콘텐츠 영역에 스켈레톤 UI 표시

## 7. Success Metrics

    * Layout Shift: CLS < 0.1
    * First Contentful Paint: FCP < 1.5s
    * 사이드바 인터랙션 응답: < 50ms
* **측정 방법:** Chrome DevTools / Lighthouse 수동 검증 (릴리스 전 체크리스트)

## 8. Security Considerations

* **Authentication:** NextAuth.js middleware로 모든 `(main)` 경로 보호, 미인증 시 로그인 페이지로 리다이렉트
* **Authorization:** 사이드바 메뉴 렌더링 시 session.user.role 기반 필터링 (클라이언트 + 서버 양측 검증)
* **Session Expiry:**
    - TanStack Query global onError에서 401 응답 시 `/login` 리다이렉트
    - SessionProvider의 `refetchOnWindowFocus: true`로 탭 전환 시 세션 확인
    - 상세 세션 갱신 전략은 별도 Auth PRD에서 정의
* **Route Protection:** 메뉴 숨김만으로는 불충분 — API Route 및 Page 레벨에서도 권한 검증 필수
