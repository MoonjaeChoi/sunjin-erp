## 1. Overview

본 PRD는 sunjin-erp 시스템의 "고객 등록 및 조회 (CRM)" 기능에 대한 요구사항을 정의한다.
이 기능은 고객사의 기본 정보(회사명, 주소, 연락처), 고객 분류(리셀러/최종고객/유지보수/일반), 고객 담당자 정보(이름, 직급, 직무, 이메일, 전화번호)를 통합적으로 등록, 조회, 수정 및 소프트 삭제할 수 있는 전자동 CRM 시스템을 제공한다.

**대상 모듈:** 고객 관리 (CRM)
**대상 사용자 역할:** USER (조회), MANAGER (CRUD 및 담당자 관리), ADMIN (전체 권한 포함 삭제)

---

## 2. Goals & Objectives

* **고객 정보 통합 관리:** 모든 고객사와 담당자 정보를 단일 시스템에서 관리하여 중복 등록 방지 및 일관성 확보
* **빠른 고객 검색 및 조회:** 고객사명, 분류, 담당 직원 등 다양한 필터링과 검색 기능으로 필요한 고객 정보를 신속하게 조회
* **고객 분류 기반 업무 흐름:** 리셀러/최종고객/유지보수/일반 고객 분류에 따라 프로젝트, 기술지원, 유지보수 등 타 모듈과의 연계 지원
* **고객 담당자 추적:** 각 고객사마다 여러 담당자를 등록하고, 업무별 담당자 지정 시 선택 가능하도록 구성
* **히스토리 추적:** 고객 정보 및 담당자 변경 이력을 기록하여 감사(audit) 요구사항 충족 [UPDATED: 모든 필드 변경 추적 (Decision 3)]
* **감정(Sentiment) 추적 (Phase 2):** 고객 만족도 또는 관계도를 기록하는 선택 필드 (향후 CRM 고도화)

## 3. User Stories / Use Cases

* **US-1:** 영업 담당자로서, 새로운 고객사의 기본 정보(회사명, 주소, 전화번호, 이메일)를 등록할 수 있다. 그래서 향후 프로젝트나 기술지원 작업 시 고객 정보를 빠르게 참조할 수 있다.
    * *Acceptance Criteria:*
        * 고객 등록 폼에서 필수 필드(회사명, 고객 분류)를 입력할 수 있다
        * 고객사명이 이미 등록되어 있으면 중복 등록 경고 표시
        * 등록 시 담당 직원(MANAGER) 자동 지정 또는 선택 지정 가능
        * 등록 성공 후 상세 페이지로 이동하여 담당자 정보 추가 가능
        * 등록 이력은 customer_created_at, created_by 기록

* **US-2:** 매니저로서, 고객 목록을 조회하고 필터링(고객 분류, 담당자, 상태)하여 팀 또는 부서별 고객을 효율적으로 관리할 수 있다.
    * *Acceptance Criteria:*
        * 고객 목록 페이지에서 고객사명으로 검색 가능
        * 고객 분류(리셀러/최종고객/유지보수/일반), 담당자, 활성 상태 등으로 필터링 가능
        * 목록에서 고객사명, 분류, 담당자, 연락처(대표 전화 또는 이메일) 표시
        * 페이지네이션 지원 (20개 항목 기본, 최대 100)
        * 정렬 지원: 고객명, 등록일, 담당자 등

* **US-3:** 영업 담당자로서, 고객 상세 페이지에서 고객 기본 정보, 담당자 리스트, 관련 프로젝트/기술지원/유지보수 계약 링크를 한 화면에서 볼 수 있다.
    * *Acceptance Criteria:*
        * 고객 상세 페이지에 기본 정보(회사명, 주소, 분류, 대표 전화, 대표 이메일) 표시
        * 담당자 탭에서 등록된 모든 담당자(이름, 직급, 부서, 이메일, 전화) 리스트 표시
        * "담당자 추가" 버튼으로 새 담당자 등록 가능
        * "관련 업무" 섹션에서 프로젝트, 기술지원, 유지보수 건 수 요약 표시
        * 각 항목 클릭 시 해당 모듈의 필터된 페이지로 이동 가능

* **US-4:** 매니저로서, 고객 담당자의 정보(이름, 직급, 부서, 이메일, 전화번호)를 추가, 수정, 삭제할 수 있다.
    * *Acceptance Criteria:*
        * 고객 상세 페이지의 "담당자" 섹션에서 담당자 추가 폼 표시
        * 담당자 추가 시 필수 필드: 이름, 직급, 이메일, 전화번호
        * 선택 필드: 부서, 직무 설명
        * 각 담당자 항목에 "수정", "삭제" 버튼 제공 (MANAGER 이상)
        * 담당자 삭제 시 soft delete (deleted_at) 처리하되, 과거 프로젝트/기술지원에는 영향 없음
        * 담당자 변경 이력 기록

* **US-5:** 사용자로서, 고객 목록 또는 고객 선택 필드에서 고객사명으로 빠르게 검색하여 선택할 수 있다.
    * *Acceptance Criteria:*
        * 검색 필드에 입력하면 고객사명 또는 고객 코드로 실시간(debounce 300ms) 자동 완성
        * 최대 10개 항목까지 드롭다운으로 표시
        * "고객 추가" 옵션으로 검색 결과 없을 시 신규 고객 등록 가능 (인라인)
        * 각 항목에 고객 분류 배지 표시

* **US-6:** 관리자(ADMIN)로서, 더 이상 활동하지 않는 고객을 소프트 삭제하여 목록에서 제외할 수 있다. [UPDATED: 대상 사용자 "관리자(ADMIN)" 명시 (Decision 1, 8)]
    * *Acceptance Criteria:*
        * 고객 상세 페이지에 "비활성화" 또는 "삭제" 버튼 제공 (ADMIN만)
        * 삭제 시 확인 대화 표시 (삭제 후 복구 불가 경고)
        * 삭제는 soft delete (deleted_at 기록), 관련된 프로젝트/기술지원/유지보수 계약은 유지
        * 삭제된 고객은 목록 및 검색에서 기본 제외 (ADMIN 필터로 조회 가능)

* **US-7:** 시스템 관리자로서, 고객 정보 변경 이력(생성, 수정, 삭제)을 조회하여 감사 추적이 가능하다. [UPDATED: 모든 필드 변경 추적 (Decision 3)]
    * *Acceptance Criteria:*
        * 고객 상세 페이지 하단에 "변경 이력" 탭 제공
        * 이력에는 변경일시, 변경자, 변경 내용(필드 + 이전값 → 새로운값) 기록
        * 담당자 추가/삭제도 이력에 기록

* **US-8:** 영업 담당자로서, 고객사별 주의 사항이나 메모를 입력하여 팀 내 정보를 공유할 수 있다.
    * *Acceptance Criteria:*
        * 고객 상세 페이지에 "메모" 필드 (최대 1000자) 제공
        * 메모 수정 이력 기록 (선택사항, Phase 2) [UPDATED: Phase 2 검토 (Decision 10)]
        * 메모는 마지막 편집자 및 편집 시각 표시

## 4. Scope

### 4.1 In-Scope

* **고객(Customer) Entity 정의 및 데이터베이스 구성**
    - 기본 정보: 고객명, 고객 분류(enum), 대표 주소, 대표 전화, 대표 이메일
    - 메타데이터: 등록일(created_at), 등록자(created_by), 수정일(updated_at), 수정자(updated_by), 소프트 삭제(deleted_at)
    - 선택 필드: 고객사 코드(코드 생성 규칙 - Oracle SEQUENCE), 산업 분야, 매출액, 종업원 수 (Phase 2)
    - 메모: CLOB 텍스트 필드

* **고객담당자(CustomerContact) Entity** [UPDATED: 독립 엔티티 확정 (Decision 4)]
    - 고객 FK, 담당자 이름, 직급, 부서, 이메일, 전화번호
    - 직무 설명, 기본 담당자 여부 (primary_contact boolean - 고객당 최대 1명)
    - 메타데이터: created_at, updated_at, deleted_at (soft delete)

* **CustomerHistory Entity (감사 추적)** [UPDATED: 모든 필드 추적 확정 (Decision 3)]
    - 고객 FK, 변경 내용(JSON), 변경자, 변경일시
    - 불변 로그 (soft delete 없음)
    - 담당자 추가/삭제도 변경 내용에 기록

* **API Route Handlers (10개)**
    - `GET /api/customers` — 목록 조회 (필터, 정렬, 페이지네이션)
    - `POST /api/customers` — 신규 고객 등록
    - `GET /api/customers/[id]` — 고객 상세 조회
    - `PUT /api/customers/[id]` — 고객 정보 수정
    - `DELETE /api/customers/[id]` — 고객 소프트 삭제 [UPDATED: ADMIN only (Decision 1, 8)]
    - `GET /api/customers/[id]/contacts` — 담당자 목록 조회
    - `POST /api/customers/[id]/contacts` — 담당자 추가
    - `PUT /api/customers/[id]/contacts/[contactId]` — 담당자 수정
    - `DELETE /api/customers/[id]/contacts/[contactId]` — 담당자 삭제 (MANAGER 가능)
    - `GET /api/customers/[id]/history` — 변경 이력 조회

* **Frontend Pages & Components**
    - 고객 목록 페이지 (`/customers`)
    - 고객 등록 페이지 (`/customers/new`)
    - 고객 상세/수정 페이지 (`/customers/[id]`)
    - CustomerList 컴포넌트 (테이블, 필터, 검색)
    - CustomerForm 컴포넌트 (등록/수정 폼)

## 5. Technical Considerations & Architecture Alignment

### 5.1 Next.js App Router Structure

* **Page Routes:**
    - `src/app/(main)/customers/page.tsx` — 고객 목록 페이지 (서버 컴포넌트)
    - `src/app/(main)/customers/new/page.tsx` — 고객 신규 등록 페이지 (서버 컴포넌트)
    - `src/app/(main)/customers/[id]/page.tsx` — 고객 상세/수정 페이지 (서버 컴포넌트)
    - `src/app/(main)/customers/[id]/loading.tsx` — 상세 페이지 로딩 스켈레톤

* **Layout:**
    - 공통 `src/app/(main)/layout.tsx` 사용 (사이드바, 헤더 포함)

* **Server vs Client Components:**
    - **Page:** Server Component (권한 검증, 데이터 초기 로딩)
    - **Form/Dialog:** Client Component (`'use client'` 지시어 사용)
    - **List/Table:** Client Component (필터, 정렬, 페이지네이션 상호작용)

**Query Parameters (GET /api/customers):**
```
page: number (default: 1, 1-indexed)
limit: number (default: 20, max: 100)
search: string (고객명 또는 코드)
```

### 5.7 입력 검증 및 보안

    - React Hook Form으로 실시간 validation 피드백

    - TypeORM parameterized queries 사용

### 5.8 성능 최적화

* **API Response Time Target:** p95 < 200ms

## 8. Security Considerations

* **Authentication:** NextAuth.js session 기반, 모든 API 호출 전 세션 검증

* **Authorization:** [UPDATED: 권한 분리 강화 (Decision 1, 8)]
    - USER: 조회 전용 (GET만 가능)
    - MANAGER: CRUD 권한 (POST/PUT/DELETE /api/customers/[id]/contacts 가능, DELETE /api/customers/[id] 불가)
    - ADMIN: 모든 권한 (DELETE /api/customers/[id] 포함)
    - API 레벨에서 권한 검증 후 응답 (프론트엔드 권한 숨김만으로 불충분)

* **Input Validation:**
    - Server-side 필수 (모든 입력값 검증)
    - XSS 방지: 사용자 입력 sanitization (Validator.js 또는 유사)
    - SQL Injection 방지: TypeORM parameterized queries
    - Email/Phone 형식 검증

* **Data Protection:**
    - 고객명, 주소, 이메일 같은 민감 데이터는 HTTPS로만 전송
    - 로그: 민감정보 마스킹 (이메일 일부, 전화번호 일부)

* **Audit Trail:** [UPDATED: 모든 필드 변경 추적 (Decision 3)]
    - 모든 CRUD 작업 이력 기록 (CustomerHistory)
    - 변경자, 변경 시각, 변경 내용 기록 (JSON 형식)
    - 담당자 추가/삭제도 이력에 기록

* **ADMIN-only Operations:** [UPDATED: 고객 삭제 ADMIN만 (Decision 1, 8)]
    - DELETE /api/customers/[id]: ADMIN만 가능
    - 의도치 않은 삭제 방지 위해 권한 제한

* **Rate Limiting:** (Phase 2)
    - 고객 등록 시도를 분당 제한 (스팸 방지)

* **CSRF 방지:**
    - NextAuth.js에서 자동 처리
