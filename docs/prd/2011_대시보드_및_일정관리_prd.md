## 1. Overview

본 PRD는 sunjin-erp 시스템의 "대시보드 및 일정관리" 기능에 대한 요구사항을 정의한다.
이 기능은 직원이 자신의 업무 일정을 캘린더 기반으로 관리하고, 업무 유형별 등록/상태 추적, 일별 상세 현황 조회를 제공하여 개인 및 팀 생산성을 가시화하는 핵심 모듈이다.

**대상 모듈:** 대시보드 & 일정관리
**대상 사용자 역할:** USER / MANAGER / ADMIN
**네비게이션 경로:** `/dashboard` (메인), `/tasks` (업무 검색)

## 2. Goals & Objectives

- **G1:** 월간/주간/일간 캘린더 뷰를 통해 업무 일정을 시각적으로 확인할 수 있다
- **G2:** 내근/외근 업무를 시각적으로 구분하여 인력 현황을 즉시 파악할 수 있다
- **G3:** 업무 유형(문서작성, 테스트, 회의, 교육, 기타)별 분류 및 상태(준비/진행/완료) 관리가 가능하다
- **G4:** 날짜별 상세 업무 리스트와 기술지원 내용을 통합 조회할 수 있다
- **G5:** MANAGER 이상 역할은 부서원의 일정을 통합 조회할 수 있다

## 3. User Stories / Use Cases

### US-1: 캘린더 뷰 조회

**As a** USER, **I want to** 월간/주간/일간 캘린더로 내 업무 일정을 확인하고 싶다, **so that** 일정 충돌 없이 업무를 계획할 수 있다.

*Acceptance Criteria:*
- 월간 뷰: 날짜 셀에 업무 건수 및 내근/외근 색상 표시
- 주간 뷰: 시간대별 업무 블록 표시
- 일간 뷰: 해당 날짜의 전체 업무 타임라인 표시
- 뷰 전환 시 URL query param으로 상태 유지 (`?view=month&date=2026-01-24`)
- 내근은 파란 계열, 외근은 주황 계열로 시각적 구분

### US-2: 업무 등록

**As a** USER, **I want to** 새 업무를 등록하고 유형/상태를 지정하고 싶다, **so that** 체계적으로 업무를 추적할 수 있다.

*Acceptance Criteria:*
- 필수 입력: 제목, 날짜, 업무 유형, 근무 형태(내근/외근)
- 선택 입력: 시작/종료 시간, 설명, 관련 고객사, 상태
- 업무 유형: 문서작성 / 테스트 / 회의 / 교육 / 기타
- 근무 형태: 내근 / 외근
- 상태: 준비 / 진행 / 완료 (기본값: 준비)
- 등록 후 캘린더 뷰에 즉시 반영 (optimistic update)

### US-3: 업무 상태 변경

**As a** USER, **I want to** 업무의 상태를 준비→진행→완료로 변경하고 싶다, **so that** 진행 현황을 실시간으로 관리할 수 있다.

*Acceptance Criteria:*
- 캘린더 또는 리스트에서 직접 상태 변경 가능
- 상태 변경 시 변경 이력 기록 (updated_at)
- 완료 시 완료일시 자동 기록

### US-4: 날짜별 상세 현황 조회

**As a** USER, **I want to** 특정 날짜의 업무 목록과 기술지원 건을 통합 조회하고 싶다, **so that** 하루 업무 전체를 한눈에 파악할 수 있다.

*Acceptance Criteria:*
- 캘린더에서 날짜 클릭 시 해당 날짜의 상세 패널 표시
- 업무(Task) 목록과 기술지원(TechSupport) 건을 구분하여 표시
- 각 항목의 유형, 상태, 시간, 고객사 정보 표시
- 기술지원 건은 읽기 전용 (기술지원 모듈에서 관리)

### US-5: 부서원 일정 조회 (MANAGER)

**As a** MANAGER, **I want to** 부서원 전체의 일정을 통합 캘린더로 조회하고 싶다, **so that** 인력 배치와 업무 분배를 효율적으로 할 수 있다.

*Acceptance Criteria:*
- MANAGER 이상 역할만 접근 가능한 "팀 캘린더" 탭
- 부서원별 색상 구분 또는 필터링
- 특정 직원 선택 시 해당 직원의 일정만 표시

### US-6: 업무 수정/삭제

**As a** USER, **I want to** 내가 등록한 업무를 수정하거나 삭제하고 싶다, **so that** 변경된 일정을 반영할 수 있다.

*Acceptance Criteria:*
- 본인이 등록한 업무만 수정/삭제 가능
- ADMIN은 모든 업무 수정/삭제 가능
- 삭제는 soft delete (deleted_at 설정)
- 삭제 전 확인 다이얼로그 표시

## 4. Scope

### 4.1 In-Scope

- 월간/주간/일간 캘린더 뷰 (3가지 모드)
- 내근/외근 시각적 구분 (색상 코딩)
- 업무 CRUD (등록/조회/수정/삭제)
- 업무 유형 분류 (문서작성, 테스트, 회의, 교육, 기타)
- 업무 상태 관리 (준비/진행/완료)
- 날짜별 상세 현황 (업무 + 기술지원 통합 조회)
- 팀 캘린더 (MANAGER 이상)
- 캘린더 날짜 이동, 오늘 버튼

### 4.2 Out-of-Scope

- 드래그 앤 드롭 일정 이동 (향후 개선)
- 반복 일정 (매주/매월 반복 설정)
- 알림/리마인더 (Push notification)
- 외부 캘린더 연동 (Google Calendar, Outlook)
- 기술지원 건의 CRUD (기술지원 모듈에서 관리)
- 업무 시간 통계/리포트 (별도 모듈)

## 5. Technical Considerations & Architecture Alignment

### 5.1 Next.js App Router Structure

**Page Routes:**
- `src/app/(main)/dashboard/page.tsx` — 대시보드 메인 (캘린더 뷰)
- `src/app/(main)/dashboard/loading.tsx` — 로딩 UI

**Client Components:**
- `src/components/features/dashboard/Calendar.tsx` — 캘린더 메인 컴포넌트
- `src/components/features/dashboard/CalendarHeader.tsx` — 뷰 전환, 날짜 이동 컨트롤
- `src/components/features/dashboard/MonthView.tsx` — 월간 뷰
- `src/components/features/dashboard/WeekView.tsx` — 주간 뷰
- `src/components/features/dashboard/DayView.tsx` — 일간 뷰
- `src/components/features/dashboard/TaskForm.tsx` — 업무 등록/수정 폼 (Dialog)
- `src/components/features/dashboard/DayDetailPanel.tsx` — 날짜별 상세 현황 패널
- `src/components/features/dashboard/TeamCalendar.tsx` — 팀 캘린더 (MANAGER용)

**Layout:** 기존 `(main)/layout.tsx` 활용 (사이드바 + 헤더)

### 5.2 API Route Handlers

- `GET /api/tasks` — 업무 목록 조회 (query: date_from, date_to, employee_id, type, status)
- `POST /api/tasks` — 업무 등록
- `GET /api/tasks/[id]` — 업무 상세 조회
- `PUT /api/tasks/[id]` — 업무 수정
- `DELETE /api/tasks/[id]` — 업무 삭제 (soft delete)
- `GET /api/dashboard/daily-summary` — 날짜별 통합 현황 (업무 + 기술지원)
- `GET /api/dashboard/team` — 팀 캘린더 데이터 (MANAGER 이상)

### 5.3 Database (Oracle XE 21c + TypeORM)

**Entity: Task**

| Column | Type | Constraint | Description |
|--------|------|-----------|-------------|
| id | NUMBER | PK, Sequence | 업무 ID |
| title | VARCHAR2(200) | NOT NULL | 업무 제목 |
| description | CLOB | NULLABLE | 업무 설명 |
| task_date | DATE | NOT NULL | 업무 날짜 |
| start_time | VARCHAR2(5) | NULLABLE | 시작 시간 (HH:MM) |
| end_time | VARCHAR2(5) | NULLABLE | 종료 시간 (HH:MM) |
| task_type | VARCHAR2(20) | NOT NULL | 업무 유형 (DOCUMENT/TEST/MEETING/TRAINING/OTHER) |
| work_type | VARCHAR2(10) | NOT NULL | 근무 형태 (OFFICE/FIELD) |
| status | VARCHAR2(10) | NOT NULL, DEFAULT 'READY' | 상태 (READY/IN_PROGRESS/DONE) |
| employee_id | NUMBER | FK → Employee(id), ON DELETE RESTRICT | 담당 직원 |
| customer_id | NUMBER | FK → Customer(id), NULLABLE, ON DELETE RESTRICT | 관련 고객사 |
| completed_at | TIMESTAMP | NULLABLE | 완료 일시 |
| created_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 생성일 |
| updated_at | TIMESTAMP | NOT NULL | 수정일 |
| deleted_at | TIMESTAMP | NULLABLE | 삭제일 (soft delete) |

**Indexes:**
- `IDX_TASK_DATE_EMPLOYEE` — (task_date, employee_id) — 날짜별 직원 조회
- `IDX_TASK_EMPLOYEE_STATUS` — (employee_id, status) — 직원별 상태 조회
- `IDX_TASK_DELETED_AT` — (deleted_at) — soft delete 필터

**Enum Values:**
- `TaskType`: DOCUMENT | TEST | MEETING | TRAINING | OTHER
- `WorkType`: OFFICE | FIELD
- `TaskStatus`: READY | IN_PROGRESS | DONE

### 5.4 State Management

- **Server State:** TanStack Query
  - `useTasksQuery(dateFrom, dateTo, filters)` — 기간별 업무 조회
  - `useDailySummaryQuery(date)` — 날짜별 통합 현황
  - `useTeamTasksQuery(dateFrom, dateTo)` — 팀 캘린더
  - `useCreateTaskMutation()` — 업무 생성 (optimistic update)
  - `useUpdateTaskMutation()` — 업무 수정
  - `useDeleteTaskMutation()` — 업무 삭제

- **Client State:** Zustand store
  - `useCalendarStore` — 현재 뷰 모드, 선택된 날짜, 선택된 직원 필터

### 5.5 Authentication & Authorization

| 본인 업무 CRUD | ✅ | ✅ | ✅ |
| 팀 캘린더 조회 | ❌ | ✅ (부서 내) | ✅ (전체) |
| 타인 업무 수정/삭제 | ❌ | ❌ | ✅ |

## 7. Success Metrics

- **SM-1:** 업무 등록 완료율 — 등록 시작 대비 완료 비율 > 90%
- **SM-2:** 캘린더 조회 응답 시간 — 월간 뷰 데이터 로딩 p95 < 300ms
- **SM-3:** 일일 활성 사용률 — DAU 기준 대시보드 접근율 > 80%
- **Technical Performance:**
  - API Response Time: p95 < 200ms (목록 조회)
  - Page Load: FCP < 1.8s, LCP < 2.5s
  - Optimistic Update: 상태 변경 즉시 반영 (UI 지연 < 100ms)

## 8. Security Considerations

- **Authentication:** NextAuth.js session 기반, 모든 API route에 인증 체크
- **Authorization:**
  - 본인 업무만 수정/삭제 가능 (employee_id === session.user.id)
  - 팀 캘린더는 MANAGER 이상만 접근 (department 기반 필터)
  - ADMIN은 전체 데이터 접근 가능
- **Input Validation:**
  - task_date: 유효한 날짜 형식
  - task_type, work_type, status: Enum 값 검증
  - title: 최대 200자, XSS 방지 (sanitize)
  - start_time, end_time: HH:MM 형식 검증, start < end 로직 체크
- **Query Injection 방지:** TypeORM parameterized query 사용
- **Rate Limiting:** 업무 등록 API에 분당 30건 제한 권장

### Open Questions

1. **캘린더 라이브러리 선택:** 자체 구현 (CSS Grid) vs `@fullcalendar/react` vs 경량 대안?

3. **팀 캘린더 성능:** 부서원 10명+ 의 월간 데이터를 한 번에 로딩할 때 성능 이슈 예상 — pagination 또는 lazy loading 필요?
4. **업무 시간 겹침 검증:** 같은 시간대에 중복 업무 등록 허용할 것인가?
5. **외근 시 위치 정보:** 향후 외근 장소(고객사 주소) 기록 필요 여부?
