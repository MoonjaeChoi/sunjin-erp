## 구현 목표

프로젝트의 Sales Pipeline 8단계 체크리스트를 개별적으로 토글(완료/미완료)하는 PATCH API를 구현한다. 체크리스트는 프로젝트 상태와 독립적으로 관리되며, 비순차적 체크를 허용한다.

### 구현 상세

#### 1. PATCH /api/projects/[id]/checklist

**Request:**
```typescript
// Method: PATCH
// URL: /api/projects/:id/checklist
// Headers: Content-Type: application/json
// Body:
{
  stage: string;      // MEETING | PROPOSAL | QUOTATION | CONTRACT | KICKOFF | DEVELOPMENT | DELIVERY | HANDOVER
  completed: boolean; // true = 완료, false = 미완료
}
```

**Response (200):**
```typescript
{
  stage: string;
  completed_at: string | null; // ISO 8601 timestamp or null
}
```

**Error Responses:**
- `400` - Invalid stage value or missing required fields
- `401` - Unauthorized (no session)
- `403` - Forbidden (RBAC 위반)
- `404` - Project not found or soft-deleted
- `500` - Internal server error

#### 3. 비즈니스 로직

```typescript
// route.ts 핵심 로직
export async function PATCH(request: Request, { params }: { params: { id: string } }) {
  // 1. 세션 검증
  const session = await getServerSession(authOptions);
  if (!session) return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });

  // 2. Request body 파싱 및 검증
  const { stage, completed } = await request.json();

  // 3. stage 유효성 검증
  const validStages = ['MEETING', 'PROPOSAL', 'QUOTATION', 'CONTRACT', 'KICKOFF', 'DEVELOPMENT', 'DELIVERY', 'HANDOVER'];
  if (!validStages.includes(stage)) {
    return NextResponse.json({ error: 'Invalid stage' }, { status: 400 });
  }

  // 4. 프로젝트 조회 (deleted_at IS NULL)
  const project = await projectRepository.findOne({
    where: { id: Number(params.id), deleted_at: IsNull() },
    relations: ['employee'],
  });
  if (!project) return NextResponse.json({ error: 'Not found' }, { status: 404 });

  // 5. RBAC 검증
  //    - USER: project.employee_id === session.user.employee_id
  //    - MANAGER: project.employee.department_id === session.user.department_id
  //    - ADMIN: 무제한
  if (!hasProjectAccess(session.user, project, 'edit')) {
    return NextResponse.json({ error: 'Forbidden' }, { status: 403 });
  }

  // 6. 컬럼 업데이트
  const columnName = STAGE_COLUMN_MAP[stage]; // e.g., 'stage_meeting_at'
  const newValue = completed ? new Date() : null; // CURRENT_TIMESTAMP or NULL

  await projectRepository
    .createQueryBuilder()
    .update(Project)
    .set({ [columnName]: newValue, updated_at: new Date() })
    .where('id = :id', { id: project.id })
    .execute();

  // 7. 응답
  return NextResponse.json({
    stage,
    completed_at: newValue ? newValue.toISOString() : null,
  });
}
```

#### 4. RBAC 검증 함수

```typescript
function hasProjectAccess(
  user: SessionUser,
  project: Project,
  action: 'view' | 'edit'
): boolean {
  if (user.role === 'ADMIN') return true;
  if (user.role === 'MANAGER') {
    return project.employee?.department_id === user.department_id;
  }
  // USER
  return project.employee_id === user.employee_id;
}
```

#### 5. 중요 규칙

- 체크리스트 변경은 프로젝트 상태(status)에 자동 영향 없음
- 비순차적 체크 허용 (예: MEETING 미완료인데 DELIVERY 완료 가능)
- COMPLETED 상태에서도 체크리스트 수정 가능
- `completed=true` 시 서버 시간(CURRENT_TIMESTAMP) 기록
- `completed=false` 시 해당 컬럼을 NULL로 설정
- `updated_at`도 함께 갱신

## Acceptance Criteria

- [ ] PATCH /api/projects/[id]/checklist 엔드포인트가 정상 동작한다
- [ ] 유효한 8개 stage 값만 허용되며, 그 외 값은 400 에러를 반환한다
- [ ] completed=true 시 해당 stage 컬럼에 CURRENT_TIMESTAMP가 기록된다
- [ ] completed=false 시 해당 stage 컬럼이 NULL로 설정된다
- [ ] 응답에 stage와 completed_at(ISO 8601 or null)이 포함된다
- [ ] RBAC: USER는 본인 담당 프로젝트만 토글 가능하다
- [ ] RBAC: MANAGER는 같은 부서 담당자의 프로젝트만 토글 가능하다
- [ ] RBAC: ADMIN은 모든 프로젝트를 토글 가능하다
- [ ] soft-deleted 프로젝트는 404를 반환한다
- [ ] 체크리스트 변경이 프로젝트 status에 영향을 주지 않는다
- [ ] 비순차적 체크가 허용된다 (이전 단계 미완료여도 체크 가능)
- [ ] updated_at이 함께 갱신된다
- [ ] 인증되지 않은 요청은 401을 반환한다
