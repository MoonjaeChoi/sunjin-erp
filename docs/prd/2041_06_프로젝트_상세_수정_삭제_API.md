#### 1. GET /api/projects/[id] - 상세 조회

**인증**: NextAuth session 필수 (미인증 시 401)

**RBAC 접근 제어:**
| 역할 | 접근 범위 |
|------|----------|
| ADMIN | 모든 프로젝트 |
| MANAGER | 부서 내 프로젝트 (employee_id의 department_id = 본인 department_id) |
| USER | 본인 담당 프로젝트 (employee_id = session.user.id) |

**JOIN:**
- CUSTOMER → customer_id, customer_name
- EMPLOYEE → employee_id, employee_name, department_id
- PROJECT_ATTACHMENT → attachments 배열 (해당 project_id의 모든 첨부파일)

#### 2. PUT /api/projects/[id] - 수정

**인증**: NextAuth session 필수

**RBAC 수정 권한:**
| 역할 | 수정 범위 |
|------|----------|
| ADMIN | 모든 프로젝트 (담당자 변경 포함) |
| MANAGER | 부서 내 프로젝트 (담당자 변경 가능: 부서 내) |
| USER | 본인 담당 프로젝트만 (담당자 변경 불가) |

**Request Body (모든 필드 선택적):**
```json
{
  "project_name": "변경된 프로젝트명",
  "project_code": "PJT-20260125-002",
  "customer_id": 2,
  "employee_id": 5,
  "status": "IN_PROGRESS",
  "start_date": "2026-02-01",
  "end_date": "2026-12-31",
  "contract_amount": 100000000,
  "description": "수정된 설명"
}
```

**검증 규칙:**
1. `project_name`: 제공 시 1~200자
2. `project_code`: 제공 시 기존 다른 프로젝트와 중복 불가 (자기 자신 제외)
3. `customer_id`: 제공 시 CUSTOMER 테이블에 존재 (deleted_at IS NULL)
4. `employee_id`: 제공 시 EMPLOYEE 테이블에 존재, USER 역할은 변경 불가
5. `status`: 상태 전이 규칙 검증
6. 날짜 순서: 최종 start_date <= end_date (기존값과 새값 조합 검증)
7. `contract_amount`: 제공 시 0 이상

**상태 전이 규칙:**

```
PREPARING ↔ IN_PROGRESS ↔ COMPLETED
     ↕            ↕            ↕
          ON_HOLD (어느 상태에서든 전환 가능)
```

| 현재 상태 | 허용 전이 |
|-----------|----------|
| PREPARING | IN_PROGRESS, ON_HOLD |
| IN_PROGRESS | PREPARING, COMPLETED, ON_HOLD |
| COMPLETED | IN_PROGRESS, ON_HOLD |
| ON_HOLD | PREPARING, IN_PROGRESS, COMPLETED (이전 상태로 복귀) |

- ADMIN: 모든 상태 전이 허용
- USER/MANAGER: 위 매트릭스 따름

**처리 로직:**
1. Session 확인
2. 프로젝트 존재 확인 (deleted_at IS NULL)
3. RBAC 권한 확인
4. Request body 검증
5. 상태 전이 검증 (status 변경 시)
6. employee_id 변경 권한 검증 (USER 불가)
7. UPDATE 실행 (updated_at 자동 갱신)

**응답:**
- 200 OK: `{ success: true }`
- 400 Bad Request: 검증 실패
- 401 Unauthorized: 미인증
- 403 Forbidden: 권한 없음
- 404 Not Found: 프로젝트 없음
- 409 Conflict: project_code 중복

#### 3. DELETE /api/projects/[id] - 소프트 삭제

**인증**: NextAuth session 필수

**RBAC 삭제 권한:**
| 역할 | 삭제 범위 |
|------|----------|
| ADMIN | 모든 프로젝트 |
| MANAGER | 부서 내 프로젝트 |
| USER | 본인 담당 프로젝트만 |

**처리 로직:**
1. Session 확인
2. 프로젝트 존재 확인 (deleted_at IS NULL)
3. RBAC 권한 확인
4. `UPDATE PROJECT SET deleted_at = CURRENT_TIMESTAMP WHERE id = :id`
5. 성공 응답 반환

**참고:** 첨부파일(PROJECT_ATTACHMENT)은 삭제하지 않음. 프로젝트 조회 시 deleted_at IS NULL 조건으로 자연스럽게 제외됨.

**응답:**
- 200 OK: `{ success: true }`
- 401 Unauthorized: 미인증
- 403 Forbidden: 권한 없음
- 404 Not Found: 프로젝트 없음

const STATUS_TRANSITIONS: Record<ProjectStatus, ProjectStatus[]> = {
  PREPARING: ['IN_PROGRESS', 'ON_HOLD'],
  IN_PROGRESS: ['PREPARING', 'COMPLETED', 'ON_HOLD'],
  COMPLETED: ['IN_PROGRESS', 'ON_HOLD'],
  ON_HOLD: ['PREPARING', 'IN_PROGRESS', 'COMPLETED'],
};

function isValidTransition(
  from: ProjectStatus,
  to: ProjectStatus,
  role: string
): boolean {
  if (role === 'ADMIN') return true;
  if (from === to) return true;
  return STATUS_TRANSITIONS[from]?.includes(to) ?? false;
}

// RBAC 권한 확인 유틸
async function checkProjectAccess(
  projectId: number,
  session: Session,
  action: 'read' | 'write'
): Promise<{ allowed: boolean; project?: Project; error?: string }> {
  const project = await findProject(projectId); // deleted_at IS NULL
  if (!project) return { allowed: false, error: 'Not Found' };

  const role = session.user.role;
  if (role === 'ADMIN') return { allowed: true, project };

  if (role === 'MANAGER') {
    const employee = await findEmployee(project.employee_id);
    if (employee.department_id !== session.user.department_id) {
      return { allowed: false, error: 'Forbidden' };
    }
    return { allowed: true, project };
  }

  // USER
  if (project.employee_id !== session.user.id) {
    return { allowed: false, error: 'Forbidden' };
  }
  return { allowed: true, project };
}
