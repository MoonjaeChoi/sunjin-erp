## 1. Overview

본 PRD는 sunjin-erp 시스템의 "프로젝트 관리 (Sales Pipeline)" 기능에 대한 요구사항을 정의한다.
이 기능은 선진인포텍의 영업 프로젝트를 고객사 및 프로젝트명 기반으로 관리하며, 영업 파이프라인의 진행 단계(회의 → 제안 → 견적 → 계약 → 착수 → 진행 → 납품 → 인수인계)를 체크리스트로 추적하는 모듈이다. 프로젝트 코드(Pjt-Code), 계약 기간, 영업 담당자, 관련 자료 첨부(복수 파일)를 통해 영업 활동을 체계적으로 관리한다.

**대상 모듈:** 프로젝트 관리 (Sales Pipeline)
**대상 사용자 역할:** ADMIN / MANAGER / USER
**네비게이션 경로:** `/projects` (사이드바 그룹 2: 영업/지원)

## 2. Goals & Objectives

* **영업 파이프라인 가시화:** 전체 프로젝트의 진행 단계를 한눈에 파악하여 영업 활동을 효율적으로 관리한다.
* **프로젝트 현황 대시보드:** 상태별(준비/진행중/완료/보류) 프로젝트 수를 집계하여 현황을 빠르게 파악한다.
* **단계별 체크리스트 관리:** 회의~인수인계까지 8단계의 진행 상황을 체크리스트로 관리하여 누락 없는 업무 진행을 보장한다.
* **계약 정보 관리:** 프로젝트 코드, 계약 기간, 계약 금액, 관련 자료(복수 파일)를 체계적으로 보관한다.
* **검색 및 필터링:** 고객사, 프로젝트명, 상태, 담당자별 복합 검색을 지원한다.

## 3. User Stories / Use Cases

* **US-1:** USER로서, 프로젝트 목록을 조회하여 담당 프로젝트의 현황을 파악할 수 있다.
    * *Acceptance Criteria:*
        * 기본적으로 본인 담당 프로젝트만 표시된다 (ADMIN은 전체, MANAGER는 부서 내)
        * 목록에 프로젝트 코드, 프로젝트명, 고객사, 상태, 담당자, 계약 기간이 표시된다
        * 프로젝트 코드 미부여 건은 "-"로 표시
        * 상태별 카운트 뱃지가 목록 상단에 표시된다 (현재 필터 범위 내 집계)
        * 페이지네이션 및 정렬 기능을 제공한다

* **US-2:** USER로서, 신규 프로젝트를 등록하여 영업 활동을 기록할 수 있다.
    * *Acceptance Criteria:*
        * 필수 입력: 프로젝트명, 고객사, 영업 담당자
        * 선택 입력: 프로젝트 코드(자동생성 버튼 또는 수동입력), 계약 시작일, 계약 종료일, 계약 금액, 설명
        * 프로젝트 코드 형식: `PJT-YYYYMMDD-NNN` (SEQUENCE 기반 NNN 생성)
        * 등록 시 초기 상태는 'PREPARING'으로 설정된다
        * 고객사는 검색 가능한 Combobox로 등록된 고객 목록에서 선택한다
        * 업무 규칙: 초기 영업 단계에서는 코드 미부여 가능, 계약 진행 시 코드 생성

* **US-3:** USER로서, 프로젝트 상세 정보를 조회하고 진행 단계 체크리스트를 확인할 수 있다.
    * *Acceptance Criteria:*
        * 프로젝트 기본 정보(코드, 고객사, 담당자, 계약 기간, 금액) 표시
        * 8단계 체크리스트 UI로 각 단계의 완료 여부 시각화
        * 각 단계의 완료 일시 표시
        * 첨부 파일 목록 표시 (복수 파일, 카테고리별)
        * 본인 담당 건에 한해 수정/삭제 버튼 활성화 (ADMIN은 모든 건 수정 가능)

* **US-4:** USER로서, 프로젝트의 진행 단계를 체크리스트로 관리할 수 있다.
    * *Acceptance Criteria:*
        * 8단계 체크리스트: 회의 → 제안 → 견적 → 계약 → 착수 → 진행 → 납품 → 인수인계
        * 각 단계를 개별적으로 완료/미완료 토글 가능 (PATCH API로 단일 stage 업데이트)
        * 완료 시 해당 시점의 timestamp 자동 기록, 미완료로 되돌리면 null 처리
        * 순서에 관계없이 체크 가능 (비순차적 체크 허용)
        * 비순차 체크 시 미완료 이전 단계를 주황색 하이라이트로 인지 유도
        * **상태-체크리스트 연동 규칙:**
            1. 체크리스트 변경은 상태에 자동 영향 없음 (독립적)
            2. 모든 단계 완료 시 "상태를 완료로 변경하시겠습니까?" toast 알림 표시 (선택적)
            3. COMPLETED 상태에서도 체크리스트 수정 가능
            4. 어떤 상태에서든 체크리스트 체크/해제 가능

* **US-5:** USER로서, 프로젝트 상태를 변경할 수 있다.
    * *Acceptance Criteria:*
        * 상태 전이: PREPARING ↔ IN_PROGRESS ↔ COMPLETED, 어느 상태에서든 ON_HOLD 전환 가능
        * ON_HOLD에서 이전 상태로 복귀 가능
        * ADMIN: 모든 상태 전이 허용
        * 상태 변경 시 updated_at 자동 갱신

* **US-6:** USER로서, 고객사, 프로젝트명, 상태, 담당자 등으로 프로젝트를 검색할 수 있다.
    * *Acceptance Criteria:*
        * 고객사 필터 (Combobox 선택)
        * 프로젝트 상태 필터 (복수 선택 가능)
        * 담당자 필터 (Employee 목록 API 활용)
        * 키워드 검색 (프로젝트명, 프로젝트 코드 기반, 2자 이상)
        * 검색 조건 변경 시 debounce 적용 (300ms)

* **US-7:** USER로서, 프로젝트에 관련 자료(계약서, 제안서 등)를 복수 첨부할 수 있다.
    * *Acceptance Criteria:*
        * 파일 첨부: PDF, DOCX, XLSX, 이미지(JPG/PNG) 지원, 파일당 최대 10MB
        * 파일별 카테고리 지정: 계약서(CONTRACT), 제안서(PROPOSAL), 견적서(QUOTATION), 보고서(REPORT), 기타(OTHER)
        * 프로젝트당 복수 파일 첨부 가능 (1:N 관계)
        * 파일은 서버 로컬 스토리지(UPLOAD_DIR)에 저장
        * 개별 파일 다운로드 및 삭제 기능

* **US-8:** ADMIN/MANAGER로서, 프로젝트 현황을 조회하고 담당자를 변경할 수 있다.
    * *Acceptance Criteria:*
        * ADMIN: 전체 프로젝트 조회/관리
        * MANAGER: employee_id의 department_id가 본인 부서와 일치하는 프로젝트만 조회/관리
        * 담당자 변경(재배정) 기능 제공

## 4. Scope

### 4.1 In-Scope

* 프로젝트 CRUD (등록, 조회, 수정, 삭제-soft delete)
* 프로젝트 목록 페이지 (필터, 정렬, 페이지네이션, 상태별 카운트)

* 프로젝트 등록 Dialog
* 8단계 Sales Pipeline 체크리스트 관리 (별도 PATCH API)
* 프로젝트 상태 관리 (PREPARING / IN_PROGRESS / COMPLETED / ON_HOLD)
* 복수 파일 첨부 (PROJECT_ATTACHMENT 테이블, 카테고리 분류)
* 프로젝트 코드 생성 (Oracle SEQUENCE 기반)

* 역할 기반 접근 제어 (MANAGER: 부서 기준)

* Summary API (권한+필터 적용 카운트)

### 4.2 Out-of-Scope

## 5. Technical Considerations & Architecture Alignment

### 5.1 Next.js App Router Structure

* **Page Routes:**
    - `src/app/(main)/projects/page.tsx` — 프로젝트 목록 페이지 (Client Component)
* **Layout:** 공통 `(main)/layout.tsx` 레이아웃 활용
* **Server vs Client Components:** 목록 페이지 전체를 Client Component로 구현 (TanStack Query 데이터 fetching + 인터랙티브 필터/테이블)

### 5.2 API Route Handlers

* `GET /api/projects` — 목록 조회 (pagination, filters, sort)
    - Query params: `page`, `page_size`, `sort_by`, `sort_order`, `customer_id`, `status`, `employee_id`, `keyword`
    - Response: `{ projects: Project[], total: number, page: number, page_size: number }`
* `POST /api/projects` — 신규 등록
    - Body: `CreateProjectRequest`
    - Response: `{ id: number }`
* `GET /api/projects/[id]` — 상세 조회
    - Response: `ProjectDetail` (체크리스트 + 첨부파일 목록 포함)
* `PUT /api/projects/[id]` — 기본 정보 수정 (상태 변경 포함)
    - Body: `UpdateProjectRequest`
* `DELETE /api/projects/[id]` — 삭제 (soft delete)
* `PATCH /api/projects/[id]/checklist` — 체크리스트 단일 stage 토글
    - Body: `{ stage: string, completed: boolean }`
    - Response: `{ stage: string, completed_at: string | null }`
* `POST /api/projects/[id]/attachments` — 파일 업로드
    - Body: FormData (file + category)
    - Response: `{ id: number, file_name: string, category: string }`
* `GET /api/projects/[id]/attachments/[attachmentId]` — 파일 다운로드
* `DELETE /api/projects/[id]/attachments/[attachmentId]` — 파일 삭제
* `GET /api/projects/summary` — 상태별 카운트 집계 (권한+필터 적용)
    - Query params: `customer_id`, `employee_id`
    - Response: `{ preparing: number, in_progress: number, completed: number, on_hold: number }`
* `POST /api/projects/generate-code` — 프로젝트 코드 생성
    - Response: `{ code: string }` (형식: `PJT-YYYYMMDD-NNN`, SEQUENCE 기반)
* `GET /api/employees/list` — Employee 목록 (담당자 필터용)
    - Response: `{ employees: [{ id: number, name: string, department_name: string }] }`

### 5.3 Database (Oracle XE 21c + TypeORM)

#### PROJECT 테이블

| 컬럼 | 타입 | NULL | 설명 |
|------|------|------|------|
| id | NUMBER (PK) | N | PROJECT_ID_SEQ 기반 자동 생성 |
| project_code | VARCHAR2(30) | Y | 프로젝트 코드 (PJT-YYYYMMDD-NNN), UNIQUE |
| project_name | VARCHAR2(200) | N | 프로젝트명 |
| customer_id | NUMBER (FK) | N | 고객사 ID → CUSTOMER.id |
| employee_id | NUMBER (FK) | N | 영업 담당자 ID → EMPLOYEE.id |
| status | VARCHAR2(20) | N | PREPARING/IN_PROGRESS/COMPLETED/ON_HOLD, DEFAULT 'PREPARING' |
| start_date | DATE | Y | 계약 시작일 |
| end_date | DATE | Y | 계약 종료일 |
| contract_amount | NUMBER | Y | 계약 금액 (원) |
| description | CLOB | Y | 프로젝트 설명 |
| stage_meeting_at | TIMESTAMP | Y | 회의 단계 완료 일시 |
| stage_proposal_at | TIMESTAMP | Y | 제안 단계 완료 일시 |
| stage_quotation_at | TIMESTAMP | Y | 견적 단계 완료 일시 |
| stage_contract_at | TIMESTAMP | Y | 계약 단계 완료 일시 |
| stage_kickoff_at | TIMESTAMP | Y | 착수 단계 완료 일시 |
| stage_development_at | TIMESTAMP | Y | 진행 단계 완료 일시 |
| stage_delivery_at | TIMESTAMP | Y | 납품 단계 완료 일시 |
| stage_handover_at | TIMESTAMP | Y | 인수인계 단계 완료 일시 |
| created_at | TIMESTAMP | N | 생성 일시 (DEFAULT CURRENT_TIMESTAMP) |
| updated_at | TIMESTAMP | N | 수정 일시 (DEFAULT CURRENT_TIMESTAMP) |
| deleted_at | TIMESTAMP | Y | 삭제 일시 (soft delete) |

#### PROJECT_ATTACHMENT 테이블

| 컬럼 | 타입 | NULL | 설명 |
|------|------|------|------|
| id | NUMBER (PK) | N | PROJECT_ATTACHMENT_ID_SEQ 기반 |
| project_id | NUMBER (FK) | N | 프로젝트 ID → PROJECT.id |
| file_path | VARCHAR2(500) | N | 서버 저장 경로 |
| file_name | VARCHAR2(200) | N | 원본 파일명 |
| file_size | NUMBER | N | 파일 크기 (bytes) |
| category | VARCHAR2(20) | N | CONTRACT/PROPOSAL/QUOTATION/REPORT/OTHER |
| created_at | TIMESTAMP | N | 업로드 일시 (DEFAULT CURRENT_TIMESTAMP) |

**Sequences:**
- `PROJECT_ID_SEQ` — PROJECT.id 생성
- `PROJECT_CODE_SEQ` — 프로젝트 코드 NNN 부분 생성
- `PROJECT_ATTACHMENT_ID_SEQ` — PROJECT_ATTACHMENT.id 생성

**Oracle 규칙 준수:**
- VARCHAR2 for string fields
- NUMBER for numeric/FK types
- CLOB for large text
- Foreign keys: ON DELETE 구문 생략 (Oracle default = restrict)
- Soft delete (deleted_at) mandatory
- CASCADE DELETE 금지

**Indexes:**
- `IDX_PROJECT_CUSTOMER` (customer_id)
- `IDX_PROJECT_EMPLOYEE` (employee_id)
- `IDX_PROJECT_STATUS` (status)
- `IDX_PROJECT_CODE` (project_code) — UNIQUE (NULL 제외)
- `IDX_PROJECT_DELETED_AT` (deleted_at)
- `IDX_PROJECT_ATTACH_PROJECT` (project_id) — PROJECT_ATTACHMENT

**CHECK Constraints:**
- `CHK_PROJECT_STATUS`: status IN ('PREPARING', 'IN_PROGRESS', 'COMPLETED', 'ON_HOLD')
- `CHK_PROJECT_DATE_ORDER`: start_date IS NULL OR end_date IS NULL OR start_date <= end_date
- `CHK_ATTACH_CATEGORY`: category IN ('CONTRACT', 'PROPOSAL', 'QUOTATION', 'REPORT', 'OTHER')

### 5.4 State Management

* **Server State (TanStack Query):**
    - `useProjectListQuery(params)` — 목록 조회
    - `useProjectDetailQuery(id)` — 상세 조회 (체크리스트+첨부파일 포함)

    - `useUpdateProjectMutation()` — 기본 정보 수정
    - `useToggleChecklistMutation()` — 체크리스트 토글 (optimistic update)
    - `useDeleteProjectMutation()` — 삭제
    - `useUploadProjectAttachmentMutation()` — 파일 업로드
    - `useDeleteProjectAttachmentMutation()` — 파일 삭제
    - `useGenerateProjectCodeMutation()` — 코드 생성
* **Client State:** React useState (필터 상태, Dialog open/close)
* **Form State:** React useState (등록/수정 폼)

### 5.5 Authentication & Authorization

* **NextAuth.js:** Session 기반 인증, 모든 API Route 보호
* **Role-based Access:**

| 역할 | 조회 범위 | 등록 | 수정 | 삭제 | 담당자 변경 |
|------|----------|------|------|------|-----------|
| ADMIN | 전체 | O | 전체 | 전체 | O |
| MANAGER | 부서 내* | O | 부서 내 | 부서 내 | 부서 내 |
| USER | 본인 담당 | O | 본인 건 | 본인 건 | X |

*부서 판별: PROJECT.employee_id → EMPLOYEE.department_id = MANAGER의 department_id

* **계약 금액 접근:** USER는 본인 담당 프로젝트의 계약 금액을 조회할 수 있다 (조회 범위 내 제한).

### 5.6 프로젝트 코드 생성 규칙

* 형식: `PJT-YYYYMMDD-NNN`
    - YYYYMMDD: 생성 요청 날짜
    - NNN: `PROJECT_CODE_SEQ.NEXTVAL` 기반 (3자리 패딩, 예: 001, 002, ...)
* Oracle SEQUENCE로 동시성 안전하게 순번 생성
* 수동 입력도 허용 (중복 검증: UNIQUE constraint)
* project_code는 NULL 허용
    - 업무 규칙: 초기 영업 단계에서는 코드 미부여, 계약 진행 시 코드 생성
    - 목록에서 코드 미부여 건은 "-"로 표시

### 5.7 Sales Pipeline 체크리스트 단계 정의

## 8. Security Considerations

* **Authentication:** NextAuth.js session 기반 인증, 모든 API route 보호
* **Authorization:** Role-based access control (RBAC) - 본인 담당 건만 수정/삭제 가능, MANAGER 부서 기준
* **Input Validation:**
    - Server-side: project_name 길이(200자), project_code 형식/중복, status enum, date 유효성, category enum
    - 파일 업로드: 확장자 whitelist(pdf/docx/xlsx/jpg/jpeg/png), 10MB 크기 제한, MIME type 검증
* **SQL Injection 방지:** TypeORM parameterized queries 사용
* **XSS 방지:** React의 기본 escape + 파일명 sanitization
* **File Security:** 업로드 경로 traversal 방지, UUID 기반 파일명으로 저장
