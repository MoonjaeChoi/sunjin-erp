# Product Requirement Document: 기술지원 관리

## 1. Overview

본 PRD는 sunjin-erp 시스템의 "기술지원 관리" 기능에 대한 요구사항을 정의한다.
이 기능은 선진인포텍의 고객사에 대한 기술지원 이력을 등록, 조회, 관리하는 모듈로, 납품설치/테스트/교육지원/유지보수/일반지원 등 유형별 지원 활동을 체계적으로 관리하고, 진행 단계(Tier bar), 지원 방법(현장/원격/전화), 완료 보고서 파일 첨부를 지원한다.

**대상 모듈:** 기술지원 관리 (Tech Support)
**대상 사용자 역할:** ADMIN / MANAGER / USER
**네비게이션 경로:** `/support` (사이드바 그룹 2: 영업/지원)

## 2. Goals & Objectives

* **기술지원 이력 통합 관리:** 고객사별, 직원별 기술지원 활동을 한 곳에서 조회하고 관리한다.
* **진행 상태 시각화:** Tier bar UI를 통해 기술지원 건의 진행 단계를 직관적으로 파악한다.
* **완료 보고서 관리:** 기술지원 완료 후 보고서 파일을 첨부하여 이력을 체계적으로 보존한다.
* **검색 및 필터링:** 기간, 고객사, 지원 유형, 상태, 담당자별 복합 검색을 지원한다.
* **대시보드 연동:** 대시보드의 일정관리에서 기술지원 건을 통합 조회할 수 있도록 연계한다.

## 3. User Stories / Use Cases

* **US-1:** USER로서, 기술지원 목록을 조회하여 본인이 담당한 지원 건의 현황을 파악할 수 있다.
    * *Acceptance Criteria:*
        * 기본적으로 본인 담당 기술지원 건만 표시된다 (ADMIN은 전체 조회 가능)
        * 목록에 고객사명, 지원 유형, 지원일, 상태, 담당자가 표시된다
        * 페이지네이션 및 정렬 기능을 제공한다

* **US-2:** USER로서, 신규 기술지원 건을 등록하여 지원 활동을 기록할 수 있다.
    * *Acceptance Criteria:*
        * 필수 입력: 제목, 고객사, 지원 유형, 지원일
        * 선택 입력: 지원 방법, 시작/종료 시간, 설명, 완료 보고서
        * 등록 시 초기 상태는 '접수'로 설정된다
        * 고객사는 등록된 고객 목록에서 선택한다

* **US-3:** USER로서, 기술지원 건의 상세 정보를 조회하고 진행 단계를 확인할 수 있다.
    * *Acceptance Criteria:*
        * Tier bar UI로 현재 진행 단계(접수 → 진행 → 완료)를 시각화한다
        * 지원 방법, 시간, 설명, 첨부 파일 등 상세 정보를 표시한다
        * 본인 담당 건에 한해 수정/삭제 버튼이 활성화된다

* **US-4:** USER로서, 기술지원 건의 상태를 변경하고 완료 보고서를 첨부할 수 있다.
    * *Acceptance Criteria:*
        * 상태 변경: 접수 → 진행 → 완료 순서로 진행 가능
        * 완료 시 완료일시가 자동 기록된다
        * 파일 첨부: PDF, DOCX, XLSX, 이미지(JPG/PNG) 지원, 최대 10MB
        * 파일은 서버 로컬 스토리지(UPLOAD_DIR)에 저장된다

* **US-5:** USER로서, 기간, 고객사, 지원 유형, 상태 등으로 기술지원 건을 검색할 수 있다.
    * *Acceptance Criteria:*
        * 날짜 범위 필터 (최대 1년)
        * 고객사명 검색 (LIKE 검색)
        * 지원 유형, 지원 방법, 상태별 필터링
        * 키워드 검색 (제목 기반, 2자 이상)
        * 검색 조건 변경 시 debounce 적용 (300ms)

* **US-6:** ADMIN으로서, 전체 직원의 기술지원 현황을 조회하고 담당자를 변경할 수 있다.
    * *Acceptance Criteria:*
        * 전체 직원의 기술지원 건 조회 가능
        * 담당자 변경(재배정) 기능 제공
        * 직원별 필터링 가능

* **US-7:** USER로서, 대시보드 캘린더에서 기술지원 일정을 확인할 수 있다.
    * *Acceptance Criteria:*
        * 대시보드 daily-summary API에 기술지원 건수가 포함된다
        * 날짜별 상세 조회 시 기술지원 건 목록이 표시된다
        * 기술지원 항목 클릭 시 상세 페이지로 이동한다

## 5. Technical Considerations & Architecture Alignment

### 5.1 Next.js App Router Structure

* **Page Route:** `src/app/(main)/support/page.tsx`
    - Server Component로 metadata 정의 및 Client Component 렌더링
    - `<Suspense>`로 감싸 loading 상태 처리
* **Layout:** 공통 `(main)/layout.tsx` 사용 (사이드바 + 헤더)
* **Client Component:** `src/components/features/support/TechSupportClient.tsx`
    - URL params 기반 상태 관리 (useSearchParams + useRouter)
    - 검색 필터, 데이터 테이블, 등록/상세 Dialog 통합

### 5.2 API Route Handlers

* `GET /api/support` — 목록 조회 (페이지네이션, 필터링, 정렬)
    - Query Params: date_from, date_to, customer_id, support_type, support_method, status, keyword, page, page_size, sort_by, sort_order
    - RBAC: USER/MANAGER → 본인 건만, ADMIN → 전체
    - Response: `{ supports: TechSupportRecord[], total: number, page: number, page_size: number }`

* `POST /api/support` — 신규 등록
    - Body: title, customer_id, support_type, support_method, support_date, start_time, end_time, description, status
    - employee_id는 session에서 자동 설정
    - Response: 201 Created

* `GET /api/support/[id]` — 상세 조회
    - RBAC: 본인 건 또는 ADMIN만 조회 가능
    - Response: TechSupportRecord (Customer 정보 포함)

* `PUT /api/support/[id]` — 수정
    - RBAC: 본인 건만 수정 가능 (ADMIN은 담당자 변경 가능)
    - 상태 변경 시 완료일시 자동 기록

* `DELETE /api/support/[id]` — 삭제 (soft delete)
    - RBAC: 본인 건 또는 ADMIN만 삭제 가능

* `POST /api/support/[id]/attachment` — 파일 업로드
    - multipart/form-data
    - 파일 크기 제한: 10MB
    - 허용 확장자: pdf, docx, xlsx, jpg, jpeg, png
    - 저장 경로: `{UPLOAD_DIR}/support/{id}/{filename}`

* `GET /api/support/[id]/attachment` — 파일 다운로드
    - Content-Disposition: attachment

* `DELETE /api/support/[id]/attachment` — 파일 삭제

### 5.3 Database (Oracle XE 21c + TypeORM)

#### TechSupport Entity

* **Table Name:** `TECH_SUPPORT`
* **Fields:**

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| id | NUMBER | PK, auto-increment (Sequence) | 기술지원 ID |
| title | VARCHAR2(200) | NOT NULL | 제목 |
| description | CLOB | nullable | 상세 설명 |
| support_date | DATE | NOT NULL | 지원 날짜 |
| start_time | NUMBER | nullable, 0~1439 | 시작 시간 (분) |
| end_time | NUMBER | nullable, 0~1439 | 종료 시간 (분) |
| support_type | VARCHAR2(20) | NOT NULL | 지원 유형 (enum) |
| support_method | VARCHAR2(20) | nullable | 지원 방법 (enum) |
| status | VARCHAR2(20) | NOT NULL, default 'RECEIVED' | 상태 (enum) |
| employee_id | NUMBER | NOT NULL, FK → EMPLOYEE(id) | 담당자 |
| customer_id | NUMBER | NOT NULL, FK → CUSTOMER(id) | 고객사 |
| attachment_path | VARCHAR2(500) | nullable | 첨부파일 경로 |
| attachment_name | VARCHAR2(200) | nullable | 원본 파일명 |
| completed_at | TIMESTAMP | nullable | 완료 일시 |
| created_at | TIMESTAMP | NOT NULL, default CURRENT_TIMESTAMP | 등록일시 |
| updated_at | TIMESTAMP | NOT NULL | 수정일시 |
| deleted_at | TIMESTAMP | nullable | 삭제일시 (soft delete) |

* **Indexes:**
    - `IDX_TECHSUPPORT_DATE_EMPLOYEE` — (support_date, employee_id)
    - `IDX_TECHSUPPORT_CUSTOMER` — (customer_id)
    - `IDX_TECHSUPPORT_STATUS` — (status)
    - `IDX_TECHSUPPORT_DELETED_AT` — (deleted_at)

* **Constraints:**
    - FK employee_id → EMPLOYEE(id) ON DELETE RESTRICT
    - FK customer_id → CUSTOMER(id) ON DELETE RESTRICT
    - CHECK (start_time IS NULL OR (start_time >= 0 AND start_time <= 1439))
    - CHECK (end_time IS NULL OR (end_time >= 0 AND end_time <= 1439))
    - CHECK (start_time IS NULL OR end_time IS NULL OR start_time < end_time)

### 5.4 State Management

* **Server State:** TanStack Query
    - `useTechSupportSearchQuery(params)` — 목록 검색
    - `useTechSupportDetailQuery(id)` — 상세 조회
    - `useCreateTechSupportMutation()` — 등록
    - `useUpdateTechSupportMutation()` — 수정
    - `useDeleteTechSupportMutation()` — 삭제
    - `useUploadAttachmentMutation()` — 파일 업로드
    - `useCustomerListQuery()` — 고객사 선택 목록

* **Client State:** URL searchParams (검색 필터 상태)

* **Query Key Factory:**
    - `techSupportKeys.all` → `['support']`
    - `techSupportKeys.list(params)` → `['support', 'list', params]`
    - `techSupportKeys.detail(id)` → `['support', 'detail', id]`

### 5.5 Authentication & Authorization

* **NextAuth.js:** 모든 `/api/support` route에서 session 확인 (401 미인증 응답)
* **RBAC:**
    - USER: 본인이 등록한 기술지원 건만 CRUD 가능
    - MANAGER: 본인 건 CRUD + 부서 내 읽기 (Phase 2-B 확장)
    - ADMIN: 전체 건 조회/수정/삭제 + 담당자 재배정
* **소유권 검증:** 수정/삭제 시 `tech_support.employee_id === session.user.id` 확인 (ADMIN 제외)

### 6.3 Tier Bar UI

진행 단계를 시각적으로 표현하는 수평 바:

```
접수 ────── 진행 ────── 완료
 [●]        [●]        [○]     ← 현재 '진행' 상태
```

* 완료된 단계: 채워진 원 + 색상 바
* 현재 단계: 강조 원 + 활성 색상
* 미도달 단계: 빈 원 + 회색 바
* 상태별 색상: 접수(gray), 진행(blue), 완료(green)

    * Page Load: FCP < 1.8s, LCP < 2.5s
    * File Upload: 10MB 이하 파일 업로드 < 3s

    - keyword parameterized query (SQL injection 방지)
    - 파일 확장자/MIME type 서버 검증
* **File Security:**
    - 업로드 경로에 직접 접근 불가 (API route를 통해서만 다운로드)

* **Data Protection:** soft delete만 허용, 물리 삭제 금지
