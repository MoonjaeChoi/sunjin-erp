## 1. Overview

본 PRD는 sunjin-erp 시스템의 "대시보드 및 일정관리" 기능에 대한 요구사항을 정의한다.
이 기능은 직원이 자신의 업무 일정을 캘린더 기반으로 관리하고, 업무 유형별 등록/상태 추적, 일별 상세 현황 조회를 제공하여 개인 및 팀 생산성을 가시화하는 핵심 모듈이다.

**대상 모듈:** 대시보드 & 일정관리
**대상 사용자 역할:** USER / MANAGER / ADMIN
**네비게이션 경로:** `/dashboard` (메인), `/tasks` (업무 검색)

## 2. Goals & Objectives

- **G1:** 월간/주간/일간 캘린더 뷰를 통해 업무 일정을 시각적으로 확인할 수 있다
- **G2:** 내근/외근 업무를 시각적으로 구분하여 인력 현황을 즉시 파악할 수 있다
- **G3:** 업무 유형(문서작성, 테스트, 회의, 교육, 기타)별 분류 및 상태(준비/진행/완료) 관리가 가능하다
- **G4:** 날짜별 상세 업무 리스트와 기술지원 내용을 통합 조회할 수 있다
- **G5:** MANAGER 이상 역할은 부서원의 일정을 통합 조회할 수 있다

## 3. User Stories / Use Cases

### US-1: 캘린더 뷰 조회

**As a** USER, **I want to** 월간/주간/일간 캘린더로 내 업무 일정을 확인하고 싶다, **so that** 일정 충돌 없이 업무를 계획할 수 있다.

*Acceptance Criteria:*
- 월간 뷰: 날짜 셀에 업무 건수 및 내근/외근 색상 표시 (CSS Grid)
- 주간 뷰: 시간순 정렬된 업무 리스트 표시 (v1은 리스트 형태)
- 일간 뷰: 해당 날짜의 시간순 정렬된 업무 리스트 표시
- 뷰 전환 시 URL query param으로 상태 유지 (`?view=month&date=2026-01-24`)
- **URL query param이 뷰 모드/날짜의 single source of truth** (`useSearchParams()` 사용)
- 내근은 파란 계열, 외근은 주황 계열로 시각적 구분

### US-2: 업무 등록

**As a** USER, **I want to** 새 업무를 등록하고 유형/상태를 지정하고 싶다, **so that** 체계적으로 업무를 추적할 수 있다.

*Acceptance Criteria:*
- 필수 입력: 제목, 날짜, 업무 유형, 근무 형태(내근/외근)
- 선택 입력: 시작/종료 시간, 설명, 관련 고객사, 상태
- 업무 유형: 문서작성 / 테스트 / 회의 / 교육 / 기타
- 근무 형태: 내근 / 외근
- 상태: 준비 / 진행 / 완료 (기본값: 준비)
- 등록 후 캘린더 뷰에 즉시 반영 (optimistic update)
- **Optimistic Update 실패 시**: `onError` 콜백에서 이전 캐시 복원 + Toast 에러 알림
- **중복 클릭 방지**: `mutation.isPending` 상태에서 등록 버튼 비활성화
- 시간 겹침 발생 시 non-blocking 경고 메시지 표시 (등록은 허용)

### US-3: 업무 상태 변경

**As a** USER, **I want to** 업무의 상태를 준비→진행→완료로 변경하고 싶다, **so that** 진행 현황을 실시간으로 관리할 수 있다.

*Acceptance Criteria:*
- 캘린더 또는 리스트에서 직접 상태 변경 가능
- 상태 변경 시 변경 이력 기록 (updated_at)
- **완료 시 `completed_at` 자동 기록 (API 레벨, 서버 시간)**
- **상태 역행(DONE→IN_PROGRESS) 시 `completed_at` NULL 처리**
- 상태 변경 API 호출 중 해당 항목 비활성화 (isPending)

### US-4: 날짜별 상세 현황 조회

**As a** USER, **I want to** 특정 날짜의 업무 목록과 기술지원 건을 통합 조회하고 싶다, **so that** 하루 업무 전체를 한눈에 파악할 수 있다.

*Acceptance Criteria:*
- 캘린더에서 날짜 클릭 시 해당 날짜의 상세 패널 표시
- 업무(Task) 목록과 기술지원(TechSupport) 건을 구분하여 표시
- 각 항목의 유형, 상태, 시간, 고객사 정보 표시
- 기술지원 건은 읽기 전용 (기술지원 모듈에서 관리)
- **Phase 3 전까지 기술지원 섹션은 빈 상태로 표시**

### US-5: 부서원 일정 조회 (MANAGER)

**As a** MANAGER, **I want to** 부서원 전체의 일정을 통합 캘린더로 조회하고 싶다, **so that** 인력 배치와 업무 분배를 효율적으로 할 수 있다.

*Acceptance Criteria:*
- MANAGER 이상 역할만 접근 가능한 "팀 캘린더" 탭
- 부서원별 색상 구분 또는 필터링
- 특정 직원 선택 시 해당 직원의 일정만 표시
- **768px 미만 화면에서는 "데스크톱에서 이용해주세요" 안내 표시**

### US-6: 업무 수정/삭제

**As a** USER, **I want to** 내가 등록한 업무를 수정하거나 삭제하고 싶다, **so that** 변경된 일정을 반영할 수 있다.

*Acceptance Criteria:*
- 본인이 등록한 업무만 수정/삭제 가능
- ADMIN은 모든 업무 수정/삭제 가능
- 삭제는 soft delete (deleted_at 설정)
- 삭제 전 확인 다이얼로그 표시
- **완료(DONE) 상태 업무 삭제 시 추가 경고 메시지 표시**

## 4. Scope

### 4.1 In-Scope

- 월간/주간/일간 캘린더 뷰 (3가지 모드, 월간은 Grid, 주간/일간은 리스트)

// 분 → HH:MM 표시
function minutesToTimeString(minutes: number): string {
  const h = Math.floor(minutes / 60).toString().padStart(2, '0');
  const m = (minutes % 60).toString().padStart(2, '0');
  return `${h}:${m}`;
}

// HH:MM 입력 → 분 변환
function timeStringToMinutes(time: string): number {
  const [h, m] = time.split(':').map(Number);
  return h * 60 + m;
}

### 5.4 State Management

- **Server State:** TanStack Query
  - `useTasksQuery(dateFrom, dateTo, filters)` — 기간별 업무 조회
  - `useDailySummaryQuery(date)` — 날짜별 통합 현황
  - `useTeamTasksQuery(dateFrom, dateTo)` — 팀 캘린더
  - `useCreateTaskMutation()` — 업무 생성 (optimistic update + rollback)
  - `useUpdateTaskMutation()` — 업무 수정
  - `useDeleteTaskMutation()` — 업무 삭제

- **Optimistic Update 패턴:**
  ```typescript
  useCreateTaskMutation = () => useMutation({
    mutationFn: createTask,
    onMutate: async (newTask) => {
      await queryClient.cancelQueries({ queryKey: ['tasks'] });
      const previous = queryClient.getQueryData(['tasks']);
      queryClient.setQueryData(['tasks'], (old) => [...old, { ...newTask, id: 'temp' }]);
      return { previous };
    },
    onError: (err, newTask, context) => {
      queryClient.setQueryData(['tasks'], context.previous);
      toast.error('업무 등록에 실패했습니다.');
    },
    onSettled: () => {
      queryClient.invalidateQueries({ queryKey: ['tasks'] });
    },
  });
  ```

- **Client State (URL-based):**
  - 뷰 모드: `useSearchParams().get('view')` — 'month' | 'week' | 'day' (기본: 'month')
  - 선택 날짜: `useSearchParams().get('date')` — ISO 날짜 문자열 (기본: 오늘)

- **Client State (Zustand):**
  - `useCalendarStore` — selectedEmployeeFilter (팀 캘린더 필터), taskFormOpen (폼 열림 상태)
  - URL에 적합하지 않은 일시적 UI 상태만 관리

### 6.3 Responsive Design

- **Desktop (1280px+):** 캘린더 + 우측 상세 패널 (2-column)
- **Tablet (768px+):** 캘린더 전체 폭, 상세 패널은 하단 또는 Sheet overlay
- **Mobile (<768px):**
  - 일간 뷰 기본, 리스트 형태
  - 업무 등록/수정은 Dialog 대신 Sheet (하단 올라옴) 사용
  - 팀 캘린더는 "데스크톱에서 이용해주세요" 안내 표시
  - 스와이프 제스처 미지원 (v1)

### 6.4 User Interactions

- 캘린더 날짜 셀 클릭 → DayDetailPanel 표시
- 날짜 셀 더블클릭 또는 "+" 버튼 → TaskForm Dialog/Sheet 열기
- 업무 항목 클릭 → 상세 조회/수정 Dialog/Sheet
- 뷰 전환(월/주/일) → URL query param 업데이트 (`router.push`), 캘린더 리렌더링
- 시간 겹침 감지 시 → 폼 내 경고 메시지 표시 (등록 진행 가능)

### 6.5 Error Handling UX

- API 호출 실패 → Toast 알림 ("업무 등록에 실패했습니다. 다시 시도해주세요.")
- Optimistic Update 롤백 → 캘린더에서 해당 항목 제거 + Toast 알림
- 네트워크 오류 → "네트워크 연결을 확인해주세요" Toast
- 권한 부족 (403) → "접근 권한이 없습니다" Toast

## 8. Security Considerations

- **Authentication:** NextAuth.js session 기반, 모든 API route에 인증 체크
- **Authorization:**
  - 본인 업무만 수정/삭제 가능 (employee_id === session.user.id)
  - 팀 캘린더는 MANAGER 이상만 접근 (department 기반 필터)
  - ADMIN은 전체 데이터 접근 가능
- **Input Validation:**
  - task_date: 유효한 날짜 형식
  - task_type, work_type, status: Enum 값 검증
  - title: 최대 200자, XSS 방지 (sanitize)
  - start_time, end_time: 0~1439 범위, start < end 로직 체크
- **Query Injection 방지:** TypeORM parameterized query 사용
- **Rate Limiting:** 업무 등록 API에 분당 30건 제한 권장
- **completed_at 보호:** 클라이언트에서 직접 수정 불가, API 레벨 자동 설정
