### 핵심 설계

1. **컬럼 식별자 규칙**
   - 대문자 UPPERCASE: `ID`, `TITLE`, `CONTENT`, `TYPE`, `AUTHOR_ID` 등
   - 소문자 quoted: `"created_at"`, `"updated_at"`, `"deleted_at"`
   - 기존 EMPLOYEE 테이블 패턴과 동일

2. **Foreign Key 제약**
   - `ON DELETE RESTRICT`: author_id, notice_id, parent_comment_id
   - `ON DELETE SET NULL`: updated_by_id (선택적 수정자)
   - CASCADE DELETE 금지 (soft delete 사용)

3. **Check Constraint**
   - `NOTICE.TYPE`: 5가지 유형만 허용
   - `NOTICE_ATTACHMENT.FILE_SIZE`: 최대 10MB

4. **Soft Delete**
   - 모든 테이블에 `"deleted_at"` 컬럼
   - Notice 삭제 시 Comment, Attachment 연쇄 soft delete (API 레벨)
