## 구현 목표

기술지원 건에 완료 보고서 파일을 첨부(업로드/다운로드/삭제)하는 API를 구현한다. 파일 보안(이중 검증, sanitize, 크기 제한)을 적용한다.

## 구현 내용

### 파일 구조

```
src/app/api/support/[id]/attachment/
└── route.ts              # POST (업로드), GET (다운로드), DELETE (삭제)
src/lib/
└── file-utils.ts         # 파일 보안 유틸리티 (sanitize, validate)
```

### 구현 상세

#### POST /api/support/[id]/attachment — 업로드

1. **인증/권한 확인**: session 필수, 본인 건 또는 ADMIN
2. **파일 수신**: `request.formData()` — multipart/form-data
3. **보안 검증**:
   - 파일 크기 ≤ 10MB
   - 확장자 allowlist: `pdf, docx, xlsx, jpg, jpeg, png`
   - MIME type allowlist 매칭 (확장자와 MIME type 일치 확인)
   - 파일명 sanitize: `../`, `/`, `\`, `<`, `>`, `&`, `"`, `'` 제거
4. **기존 파일 처리**: attachment_path가 이미 있으면 기존 파일 물리 삭제
5. **파일 저장**:
   - UUID 생성: `{uuid}.{ext}`
   - 저장 경로: `{UPLOAD_DIR}/support/{id}/{uuid}.{ext}`
   - 디렉토리 생성 (`mkdir -p` 동등)
   - 파일 쓰기 + chmod 644
6. **DB 업데이트**: `attachment_path`, `attachment_name` 설정

#### GET /api/support/[id]/attachment — 다운로드

1. **인증/권한 확인**: 상세 조회 권한과 동일 (본인 건 또는 ADMIN)
2. **파일 존재 확인**: attachment_path가 null이면 404
3. **파일 읽기**: `fs.readFile`
4. **응답 헤더**:
   - `Content-Type`: 확장자 기반 MIME type
   - `Content-Disposition`: `attachment; filename="원본파일명"`

#### DELETE /api/support/[id]/attachment — 삭제

1. **인증/권한 확인**: 본인 건 또는 ADMIN
2. **파일 물리 삭제**: `fs.unlink`
3. **DB 업데이트**: `attachment_path = null`, `attachment_name = null`

### 핵심 인터페이스

```typescript
// src/lib/file-utils.ts

// 허용 확장자-MIME 매핑
const ALLOWED_FILE_TYPES: Record<string, string[]> = {
  pdf: ['application/pdf'],
  docx: ['application/vnd.openxmlformats-officedocument.wordprocessingml.document'],
  xlsx: ['application/vnd.openxmlformats-officedocument.spreadsheetml.sheet'],
  jpg: ['image/jpeg'],
  jpeg: ['image/jpeg'],
  png: ['image/png'],
};

const MAX_FILE_SIZE = 10 * 1024 * 1024; // 10MB

export function validateFile(file: File): { valid: boolean; error?: string } {
  // 크기 검증
  if (file.size > MAX_FILE_SIZE) {
    return { valid: false, error: 'File size exceeds 10MB limit' };
  }

  // 확장자 추출 + 검증
  const ext = file.name.split('.').pop()?.toLowerCase();
  if (!ext || !ALLOWED_FILE_TYPES[ext]) {
    return { valid: false, error: 'File type not allowed' };
  }

  // MIME type 검증 (확장자와 매칭)
  if (!ALLOWED_FILE_TYPES[ext].includes(file.type)) {
    return { valid: false, error: 'MIME type mismatch' };
  }

  return { valid: true };
}

export function sanitizeFilename(name: string): string {
  return name
    .replace(/[\/\\]/g, '')       // 경로 구분자 제거
    .replace(/\.\./g, '')         // 상위 디렉토리 참조 제거
    .replace(/[<>"'&]/g, '')      // XSS 관련 문자 제거
    .trim();
}

export function getMimeType(ext: string): string {
  const mimeMap: Record<string, string> = {
    pdf: 'application/pdf',
    docx: 'application/vnd.openxmlformats-officedocument.wordprocessingml.document',
    xlsx: 'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet',
    jpg: 'image/jpeg',
    jpeg: 'image/jpeg',
    png: 'image/png',
  };
  return mimeMap[ext] || 'application/octet-stream';
}
```

## Acceptance Criteria

- [ ] POST: multipart/form-data 업로드 동작
- [ ] POST: 10MB 초과 시 400 응답
- [ ] POST: 허용되지 않은 확장자 거부 (400)
- [ ] POST: MIME type 불일치 거부 (400)
- [ ] POST: 파일명 sanitize 동작 (경로 탐색 문자 제거)
- [ ] POST: UUID 파일명으로 저장
- [ ] POST: 기존 파일 존재 시 교체 (기존 물리 삭제 + 새 파일 저장)
- [ ] POST: DB에 attachment_path, attachment_name 업데이트
- [ ] POST: chmod 644 적용
- [ ] GET: 파일 다운로드 + Content-Disposition 헤더
- [ ] GET: 첨부 없는 건 404 응답
- [ ] GET: RBAC (본인 건/ADMIN)
- [ ] DELETE: 파일 물리 삭제 + DB null 처리
- [ ] DELETE: RBAC (본인 건/ADMIN)
- [ ] 모든 route: 미인증 시 401
