### 2. 검색 쿼리 최적화

**GET /api/customers 검색 쿼리 성능 개선**:

**현재 문제점**:
- LIKE 검색: `%search%` 패턴은 인덱스 활용 불가
- 대량 데이터셋에서 느린 응답

**최적화 전략**:

#### 옵션 1: Full-Text Search (권장하지 않음 - Oracle XE 미지원)

#### 옵션 2: 부분 인덱스 최적화 (권장)

```sql
-- 현재 인덱스
CREATE INDEX idx_customer_name ON CUSTOMER(name);

-- 개선: 앞 글자 검색 인덱스 추가
CREATE INDEX idx_customer_name_prefix ON CUSTOMER(SUBSTR(name, 1, 10));

-- 코드 검색 인덱스 (정확한 매칭)
CREATE UNIQUE INDEX idx_customer_code ON CUSTOMER(code);
```

#### 옵션 3: 애플리케이션 레벨 최적화

```typescript
// 검색 쿼리 최적화
let whereClause = 'WHERE c.deleted_at IS NULL';

if (search) {
  // 정확한 매칭 우선 (code로 검색)
  whereClause += ` AND (c.code = :search OR LOWER(c.name) LIKE LOWER(:searchPrefix) OR LOWER(c.name) LIKE LOWER(:searchLike))`;
  params.search = search;
  params.searchPrefix = `${search}%`;  // 앞 글자 매칭
  params.searchLike = `%${search}%`;   // 전체 매칭 (폴백)
}

// 정렬 순서: code 정확 매칭 > name 앞 글자 > name 포함
const sql = `
  SELECT c.*, e.name as manager_name
  FROM CUSTOMER c
  LEFT JOIN EMPLOYEE e ON c.created_by_id = e.id
  ${whereClause}
  ORDER BY
    CASE WHEN c.code = :search THEN 1 ELSE 2 END,
    CASE WHEN c.name LIKE :searchPrefix THEN 1 ELSE 2 END,
    c.name ASC
  OFFSET :offset ROWS FETCH NEXT :limit ROWS ONLY
`;
```
