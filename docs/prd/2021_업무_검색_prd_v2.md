## 1. Overview

본 PRD는 sunjin-erp 시스템의 "업무 검색 (통합 조회)" 기능에 대한 요구사항을 정의한다.
이 기능은 날짜(기간), 고객사명, 업무 유형, 직원별 복합 검색을 지원하여 등록된 업무를 테이블 형태로 조회하고, RBAC에 따라 조회 범위를 제어하는 통합 검색 페이지를 제공한다.

대시보드가 개인 캘린더 중심의 일정 관리 뷰라면, 업무 검색은 조건 기반 필터링과 데이터 테이블 뷰를 통한 다건 조회/분석에 초점을 맞춘다.

**대상 모듈:** 업무 검색
**대상 사용자 역할:** USER / MANAGER / ADMIN
**네비게이션 경로:** `/tasks`

---

## 2. Goals & Objectives

- **G1:** 날짜 범위, 고객사명, 업무 유형, 직원, 상태, 근무 형태를 조합한 복합 검색을 제공한다.
- **G2:** 검색 결과를 페이지네이션된 데이터 테이블로 표시하여 대량 데이터 조회를 지원한다.
- **G3:** RBAC에 따라 USER/MANAGER는 본인 업무만(Phase 2-A), MANAGER는 부서 내(Phase 2-B), ADMIN은 전체 업무를 조회한다.
- **G4:** 검색 조건을 URL query param으로 유지하여 브라우저 히스토리/북마크/공유를 지원한다.
- **G5:** 검색 결과에서 개별 업무 상세 정보를 확인하고 수정할 수 있다.
- **G6:** 필터 변경 시 debounce를 적용한 즉시 검색으로 빠른 피드백을 제공한다.

## 3. User Stories / Use Cases

### US-1: 복합 조건 검색

**As a** USER, **I want to** 기간, 업무 유형, 상태 등 조건을 조합하여 업무를 검색하고 싶다, **so that** 특정 조건의 업무 이력을 빠르게 찾을 수 있다.

*Acceptance Criteria:*
- 검색 필터: 날짜 범위(시작~종료), 업무 유형, 근무 형태, 상태, 키워드(제목)
- 날짜 범위 기본값: 현재 월 1일 ~ 말일
- **최대 검색 기간: 1년(365일).** 초과 시 에러 메시지 표시
- 필터 변경 시 **debounce 적용 후 즉시 검색** (Select/DatePicker: 300ms, 키워드: 500ms)
- URL query param 동기화 (debounce 후 업데이트, 브라우저 뒤로가기로 이전 검색 복원)
- 초기화 버튼으로 모든 필터를 기본값으로 리셋
- **페이지 최초 접근 시 기본 날짜 범위(현재 월)로 자동 검색**
- **키워드 최소 2자 이상** 입력 시 필터 적용

### US-2: 직원별 검색 (Phase 2-B)

**As a** MANAGER, **I want to** 부서 내 직원의 업무를 검색하고 싶다, **so that** 팀원의 업무 현황을 파악할 수 있다.

*Acceptance Criteria:*
- **Phase 2-A:** 직원 선택 필터 미표시. USER/MANAGER 모두 본인 업무만 조회. ADMIN만 전체 조회.
- **Phase 2-B (Phase 1 완료 후):**
  - MANAGER: 직원 선택 드롭다운에 부서 내 직원 목록 표시
  - ADMIN: 직원 선택 드롭다운에 전체 직원 목록 표시
  - 직원 미선택 시: MANAGER는 부서 전체, ADMIN은 전체 직원 업무 조회

### US-3: 고객사별 검색 (Phase 2-B)

**As a** USER, **I want to** 고객사명으로 업무를 검색하고 싶다, **so that** 특정 고객 관련 업무 이력을 확인할 수 있다.

*Acceptance Criteria:*
- **Phase 2-A:** 고객사 검색 필터 미표시
- **Phase 2-B (Phase 1 Customer 모듈 완료 후):**
  - 고객사 검색 입력: 텍스트 입력 시 자동완성(autocomplete) 제공
  - Customer 엔티티와 JOIN하여 고객사명으로 필터링
  - 고객사가 지정되지 않은 업무도 결과에 포함 (필터 미적용 시)

### US-4: 검색 결과 테이블

**As a** USER, **I want to** 검색 결과를 테이블로 확인하고 싶다, **so that** 업무 내역을 일목요연하게 파악할 수 있다.

*Acceptance Criteria:*
- 테이블 컬럼: 날짜, 제목, 업무 유형, 근무 형태, 상태, 시간(시작~종료)
  - Phase 2-B 추가 컬럼: 직원명(MANAGER/ADMIN), 고객사명
- 서버사이드 페이지네이션 (기본 20건/페이지, 10/20/50 선택 가능)
- 컬럼 헤더 클릭 시 정렬 (날짜, 제목, 상태). **단일 컬럼 정렬만 지원.**
- **기본 정렬: `task_date DESC` (최신 순)**
- 결과 건수 표시 (예: "총 142건")
- 결과 없음 시 빈 상태 메시지 표시
- **이전 데이터 유지:** 페이지 전환/필터 변경 시 이전 결과를 placeholder로 표시 (깜빡임 방지)

### US-5: 업무 상세 조회/수정

**As a** USER, **I want to** 검색 결과에서 업무를 클릭하여 상세 정보를 확인하고 수정하고 싶다, **so that** 업무 내용을 갱신할 수 있다.

*Acceptance Criteria:*
- 테이블 행 클릭 시 **Dialog**로 상세 표시
- **URL에 `?detail={id}` param 추가** (공유/북마크 지원)
- 페이지 새로고침 또는 직접 URL 접근 시 해당 Dialog 자동 열림
- 상세 화면에서 업무 정보 수정 가능 (제목, 설명, 상태, 시간 등)
- 수정 후 테이블 데이터 자동 갱신 (invalidateQueries)
- 본인 업무만 수정 가능 (타인 업무는 읽기 전용)

### US-6: 검색 결과 내보내기 (Phase 2-B)

**As a** MANAGER/ADMIN, **I want to** 검색 결과를 CSV로 내보내고 싶다, **so that** 보고서 작성에 활용할 수 있다.

*Acceptance Criteria:*
- **Phase 2-A:** 내보내기 기능 미표시
- **Phase 2-B:**
  - 내보내기 버튼 클릭 시 현재 검색 조건 기준 CSV 다운로드
  - **최대 5,000건 제한.** 초과 시 에러: "검색 결과가 5,000건을 초과합니다. 날짜 범위를 좁혀주세요."
  - CSV 컬럼: 날짜, 제목, 업무 유형, 근무 형태, 상태, 시작시간, 종료시간, 직원명, 고객사명
  - UTF-8 BOM 포함 (Excel 한글 호환)
  - USER 역할은 내보내기 기능 미표시

## 4. Scope

### 4.1 Phase 2-A (즉시 구현)

- 복합 조건 검색 필터 UI (날짜 범위, 업무 유형, 근무 형태, 상태, 키워드)
- 즉시 검색 (debounce 300ms/500ms)

- URL query param 기반 상태 관리
- RBAC: USER/MANAGER 본인만, ADMIN 전체
- 업무 상세 조회 Dialog (URL param 동기화)
- 업무 수정 (본인 업무에 한함)
- 날짜 범위 최대 1년 제한
- 기본 정렬 task_date DESC
- 키워드 최소 2자 제한

### 4.2 Phase 2-B (Phase 1 완료 후)

- 직원 선택 드롭다운 (Employee 엔티티 기반)
- MANAGER 부서 범위 필터링

- CSV 내보내기 (MANAGER/ADMIN, 최대 5,000건)

### 4.3 Out-of-Scope

- 업무 신규 등록 (대시보드 TaskForm에서 처리)

- 기술지원 통합 조회 (기술지원 모듈에서 별도 구현)
- 엑셀(xlsx) 내보내기 (CSV만 지원)
- 검색 조건 저장/프리셋 기능
- 대량 일괄 수정
- 다중 컬럼 정렬

## 5. Technical Considerations & Architecture Alignment

### 5.1 Next.js App Router Structure

- **Page Route:** `src/app/(main)/tasks/page.tsx` — 업무 검색 페이지 (기존 placeholder 교체)
- **Layout:** `src/app/(main)/layout.tsx` 공통 레이아웃 활용
- **Component Pattern:**
  - Page (Server Component): searchParams를 TaskSearchClient에 전달
  - TaskSearchClient (Client Component): 필터 UI + 테이블 + 페이지네이션 + Dialog
  - TaskDetailDialog (Client Component): 상세 조회/수정 모달

### 5.2 API Route Handlers

**기존 `GET /api/tasks` 하위 호환 확장:**

- `GET /api/tasks` — 목록 조회
  - **하위 호환:** `page` 미지정 시 기존 동작 유지 (전체 반환, `{ tasks, total }`)
  - **페이지네이션 모드:** `page` 지정 시 `{ tasks, total, page, page_size }` 반환
  - 추가 query params: `keyword`, `work_type`, `page`, `page_size`, `sort_by`, `sort_order`
  - `keyword`: 최소 2자 이상. `title LIKE '%keyword%'` (parameterized)
  - `sort_by`: `task_date` (default) | `title` | `status`
  - `sort_order`: `DESC` (default) | `ASC`
  - `page_size`: 10 | 20 (default) | 50. 최대 100
  - RBAC: Phase 2-A에서 USER/MANAGER=본인, ADMIN=전체
  - 날짜 범위 최대 365일 검증
- `GET /api/tasks/[id]` — 상세 조회 (기존)
- `PUT /api/tasks/[id]` — 수정 (기존, employee_id 소유권 검증)
- `GET /api/tasks/export` — CSV 내보내기 (Phase 2-B)
  - 최대 5,000건 제한
  - MANAGER/ADMIN만 접근 가능
- `GET /api/customers/search` — 고객사 자동완성 (Phase 2-B)

### 5.3 Database (Oracle XE 21c + TypeORM)

- **기존 Entity 활용:** `Task` 엔티티 (`src/entities/Task.ts`)
- **인덱스 활용:**
  - `IDX_TASK_EMPLOYEE_DATE` (employee_id, task_date, deleted_at) — RBAC 필터 + 날짜 범위
  - `IDX_TASK_DATE_EMPLOYEE` (task_date, employee_id) — 날짜 기반 조회
- **페이지네이션:** TypeORM `skip()`/`take()` → Oracle `OFFSET ... FETCH NEXT ... ROWS ONLY`
- **정렬:** TypeORM `orderBy()` 동적 적용
- **keyword 검색:** `task.title LIKE :keyword` (parameterized query, 최소 2자)
- **Phase 2-B 추가:**
  - Customer Entity JOIN (LEFT JOIN, customer_id nullable)
  - Employee Entity JOIN (직원명 표시)

### 5.4 State Management

- **URL State (Single Source of Truth):** `useSearchParams()` + `useRouter()`
  - 필터 params: `date_from`, `date_to`, `type`, `work_type`, `status`, `keyword`
  - 테이블 params: `page`, `page_size`, `sort_by`, `sort_order`
  - Dialog param: `detail` (task ID)
  - Phase 2-B 추가: `employee_id`, `customer_id`
- **Server State:** TanStack Query
  - queryKey: `['tasks', 'search', { ...filterParams }]`
  - `placeholderData`: 이전 데이터 유지 (페이지 전환 시 깜빡임 방지)
  - `enabled`: 날짜 범위가 유효할 때만 fetch
- **Client State:** `useState`로 debounced filter values 관리
- **Debounce 로직:** 필터 변경 → debounce → URL param 업데이트 → TanStack Query 자동 refetch

### 5.5 Authentication & Authorization

- **Route Protection:** middleware.ts에서 인증 확인
- **API Level RBAC (Phase 2-A):**
  - USER: `task.employee_id = session.user.id`
  - MANAGER: `task.employee_id = session.user.id` (본인만)
  - ADMIN: 필터 없음 (전체 조회)
- **API Level RBAC (Phase 2-B):**
  - MANAGER: `task.employee_id IN (부서 내 직원 ID 목록)`
- **수정 권한:** `task.employee_id === session.user.id` 검증 (모든 역할 동일)
- **내보내기 권한:** MANAGER/ADMIN만 (Phase 2-B)

### 6.3 Responsive Design

- **Desktop (1280px+):** 필터 영역 2행 그리드, 테이블 전체 컬럼 표시
- **Tablet (768px+):** 필터 영역 세로 배치, 테이블 수평 스크롤
- 날짜/제목/상태는 항상 표시, 시간/유형/형태는 breakpoint에 따라 숨김 가능

### 6.4 User Feedback

- **검색 중:** 테이블 영역 Skeleton 표시 (이전 데이터 placeholder 유지)
- **결과 없음:** 빈 상태 아이콘 + "검색 조건에 맞는 업무가 없습니다" 메시지
- **날짜 범위 초과:** 인라인 에러 "검색 기간은 최대 1년입니다"
- **수정 성공:** Toast 알림 "업무가 수정되었습니다"
- **내보내기 초과(Phase 2-B):** Toast 에러 "검색 결과가 5,000건을 초과합니다"

## 7. Success Metrics

- **검색 응답 속도:** API p95 < 300ms (페이지네이션 적용 상태)
- **페이지 로드:** FCP < 1.8s, LCP < 2.5s
- **즉시 검색 피드백:** debounce 후 결과 갱신까지 체감 지연 < 500ms
- **데이터 정확성:** RBAC에 따른 검색 범위 일치율 100%
- **URL 상태 동기화:** 브라우저 뒤로가기/새로고침 시 검색 조건 및 결과 유지

## 8. Security Considerations

- **Authentication:** 모든 API route에서 NextAuth session 확인
- **Authorization:**
  - API level에서 RBAC 강제 적용 (클라이언트 필터링에만 의존하지 않음)
  - 수정 API에서 `task.employee_id === session.user.id` 검증
  - 내보내기 API에서 MANAGER/ADMIN role 검증 (Phase 2-B)
- **Input Validation:**
  - 날짜 파라미터 형식 검증 (ISO date string)
  - **날짜 범위 최대 365일 검증**
  - keyword: **최소 2자, 최대 100자** 제한
  - keyword 파라미터 SQL injection 방지 (parameterized query)
  - page_size: 10/20/50만 허용 (최대 100)
  - sort_by: whitelist 검증 (`task_date`, `title`, `status`)
  - sort_order: `ASC`/`DESC`만 허용
  - customer_id, employee_id 숫자 타입 검증
- **Data Protection:**
  - CSV 내보내기 시 민감 정보 제외
  - **CSV 최대 5,000건 제한**으로 대량 데이터 추출 방지
