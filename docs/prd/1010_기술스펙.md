## 1. 기술 스택

### 1.1 핵심 기술

| 계층 | 기술 | 버전 | 선정 이유 |
|------|------|------|-----------|
| **Frontend** | Next.js (App Router) + TypeScript | 14.2.x | SSR/SSG 지원, 파일 기반 라우팅 |
| **UI 라이브러리** | shadcn/ui + Tailwind CSS | 3.4.x | 커스터마이징 용이, 접근성 기본 지원 |
| **상태관리** | Zustand + TanStack Query | 4.5.x / 5.50.x | 경량, 서버 상태와 클라이언트 상태 분리 |
| **Backend API** | Next.js Route Handlers | - | 별도 서버 불필요, 풀스택 단일 프로젝트 |
| **ORM** | TypeORM | 0.3.28 | Oracle 공식 지원, 타입 안전 쿼리 |
| **Database** | Oracle XE 21c | 21.3.0 | 무료 사용 가능, 엔터프라이즈급 안정성 |
| **인증** | NextAuth.js | 4.24.x | JWT 세션, 역할 기반 접근 제어 |
| **배포** | Docker + Docker Compose | - | 온프레미스 또는 클라우드 유연 배포 |

## 3. 데이터베이스 스키마

### 3.1 엔티티 관계도

```
[Department] ──── [Employee] ─┬── [Task]
                               ├── [TechSupport] ──── [Customer]
                               ├── [Project] ────── [Customer]
                               └── [Issue] ─────── [Customer]

[Customer] ─┬── [CustomerContact]
            ├── [CustomerHistory]
            ├── [MaintenanceContract] ─┬── [MaintenanceContractAttachment]
            │                          └── [MaintenanceContractHistory]
            └── [Project] ──── [ProjectAttachment]

[Issue] ─┬── [IssueAttachment]
         └── [IssueHistory]

[Inventory] ──── [InventoryHistory]
```

### 3.2 엔티티 목록 (16개)

| 엔티티 | 테이블 | 설명 | 핵심 필드 |
|--------|--------|------|-----------|
| `Employee` | employees | 직원 | id, name, email, department_id, position_id, role |
| `Customer` | customers | 고객사 | id, code, name, type, address, memo |
| `CustomerContact` | customer_contacts | 고객 담당자 | id, customer_id, name, phone, email, is_primary |
| `CustomerHistory` | customer_histories | 고객 변경 이력 | id, customer_id, action, changes |
| `Task` | tasks | 업무 | id, employee_id, task_date, title, type, status, location |
| `TechSupport` | tech_supports | 기술지원 | id, customer_id, employee_id, support_type, method, status |
| `Project` | projects | 프로젝트 | id, customer_id, code, name, status, checklist |
| `ProjectAttachment` | project_attachments | 프로젝트 첨부 | id, project_id, category, file_path |
| `Issue` | issues | 장애 | id, customer_id, assignee_id, severity, status |
| `IssueAttachment` | issue_attachments | 장애 첨부 | id, issue_id, file_path, file_name |
| `IssueHistory` | issue_histories | 장애 이력 | id, issue_id, action, changes |
| `Inventory` | inventory | 재고 | id, category, model_name, serial_number, status, location |
| `InventoryHistory` | inventory_histories | 입출고 이력 | id, inventory_id, action, details |
| `MaintenanceContract` | maintenance_contracts | 유지보수 계약 | id, customer_id, contract_name, start_date, end_date |
| `MaintenanceContractAttachment` | maintenance_contract_attachments | 계약 첨부 | id, contract_id, file_path |
| `MaintenanceContractHistory` | maintenance_contract_histories | 계약 이력 | id, contract_id, action, changes |

### 3.3 공통 컬럼 규칙

- **PK**: `id` (NUMBER, 시퀀스 자동 생성)
- **생성/수정 추적**: `created_at`, `updated_at`, `created_by`, `updated_by`
- **Soft Delete**: `deleted_at` (물리 삭제 금지)
- **문자열**: `VARCHAR2` (NOT VARCHAR)
- **큰 텍스트**: `CLOB`

## 5. 인증 및 권한

### 5.1 역할 기반 접근 제어 (RBAC)

| 역할 | 설명 | 권한 |
|------|------|------|
| `ADMIN` | 시스템 관리자 | 전체 기능 + 직원/부서 관리 |
| `MANAGER` | 부서 관리자 | 부서 내 데이터 조회/편집 |
| `USER` | 일반 사용자 | 본인 데이터 관리 + 공용 데이터 읽기 |

### 5.2 모듈별 권한 매트릭스

| 모듈 | ADMIN | MANAGER | USER |
|------|-------|---------|------|
| 직원 관리 | CRUD | R | - |
| 부서/직급 관리 | CRUD | R | R |
| 고객 관리 | CRUD | CRU | R |
| 프로젝트 | CRUD | CRUD (부서) | CRU (본인) |
| 장애 관리 | CRUD | CRUD (부서) | CRU (본인) |
| 재고 관리 | CRUD | RU (출고/반납) | R |
| 유지보수 | CRUD | RU | R |
