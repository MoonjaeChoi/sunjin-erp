## 1. 기술 스택

| 계층 | 기술 | 선정 이유 |
|------|------|-----------|
| **Frontend** | Next.js 14 (App Router) + TypeScript | SSR/SSG 지원, 파일 기반 라우팅 |
| **UI 라이브러리** | shadcn/ui + Tailwind CSS | 커스터마이징 용이, 접근성 기본 지원, 일관된 디자인 시스템 |
| **상태관리** | Zustand (클라이언트) + TanStack Query (서버 상태) | 경량, 보일러플레이트 최소화 |
| **Backend API** | Next.js Route Handlers (API Routes) | 별도 서버 불필요, 풀스택 단일 프로젝트 |
| **ORM** | TypeORM | Oracle 공식 지원, 타입 안전 쿼리, 마이그레이션 관리 |
| **Database** | Oracle XE 23 (Express Edition) | 무료 사용 가능, 엔터프라이즈급 안정성, 관계형 데이터 적합 |
| **인증** | NextAuth.js (Auth.js v5) | 세션/JWT 지원, 역할 기반 접근 제어 |
| **파일 저장소** | 로컬 스토리지 | 첨부파일(계약서, 보고서) 관리 |
| **배포** | Docker + Docker Compose | 온프레미스 또는 클라우드 유연 배포 |

## 3. 데이터베이스 스키마 (핵심 엔티티)

### 3.1 엔티티 관계도

```
[Employee] ─┬─── [Task] (업무)
             ├─── [TechSupport] (기술지원)
             ├─── [Project] (프로젝트)
             └─── [Issue] (장애)

[Customer] ─┬─── [CustomerContact] (담당자)
             ├─── [MaintenanceContract] (유지보수 계약)
             ├─── [Project]
             └─── [Issue]

[Department] ──── [Employee]

[Inventory] ──── [InventoryHistory] (입출고 이력)

[Notice] ──── [NoticeComment] (댓글)
```

### 3.2 주요 테이블

| 테이블 | 설명 | 핵심 필드 |
|--------|------|-----------|
| `employees` | 직원 | id, name, department_id, position, email, role(권한) |
| `departments` | 부서 | id, name |
| `customers` | 고객사 | id, name, type(리셀러/최종고객/유지보수/일반) |
| `customer_contacts` | 고객 담당자 | id, customer_id, name, phone, position |
| `tasks` | 업무 | id, employee_id, date, type(문서작성/테스트/회의/교육/기타), status, location(내근/외근) |
| `tech_supports` | 기술지원 | id, customer_id, employee_id, type(납품설치/테스트/교육/유지보수/일반), method(현장/원격/전화), stage, status |
| `projects` | 프로젝트 | id, customer_id, code, name, start_date, end_date, stage, sales_rep_id |
| `project_checklists` | 체크리스트 | id, project_id, step_name, is_completed |
| `issues` | 장애 | id, customer_id, reporter_id, handler_id, method, status, result |
| `inventory` | 재고 | id, category, model, serial_no, location |
| `inventory_histories` | 입출고 이력 | id, inventory_id, type(입고/출고), date, operator_id |
| `maintenance_contracts` | 유지보수 계약 | id, customer_id, name, start_date, end_date, sales_rep_id |
| `notices` | 공지사항 | id, author_id, type(공지/공유/지시/건의/자유), title, content, view_count |
| `notice_comments` | 댓글 | id, notice_id, author_id, content |
| `attachments` | 첨부파일 | id, entity_type, entity_id, file_path, file_name |

## 4. 모듈별 구현 우선순위

| 단계 | 모듈 | 이유 |
|------|------|------|
| **Phase 1** | 인증 + 직원관리 + 고객관리 | 기반 데이터 (다른 모듈의 의존성) |
| **Phase 2** | 대시보드 + 업무관리 + 업무검색 | 일상 업무의 핵심 기능 |
| **Phase 3** | 기술지원 + 장애관리 | 고객 서비스 핵심 |
| **Phase 4** | 프로젝트 관리 (Sales Pipeline) | 영업 프로세스 |
| **Phase 5** | 재고관리 + 유지보수 관리 | 자산/계약 관리 |
| **Phase 6** | 공지사항 | 커뮤니케이션 (독립적) |

## 5. 주요 UI/UX 고려사항

- **대시보드 캘린더**: FullCalendar 라이브러리 활용, 내근(파란색)/외근(초록색) 시각적 구분
- **Tier Bar UI (기술지원)**: 단계별 진행 상태를 Stepper 컴포넌트로 표현
- **Sales Pipeline**: Kanban 보드 형태 (준비 → 진행중 → 완료)
- **통합 검색**: 날짜 범위 피커 + 다중 필터 조합
- **반응형**: 데스크톱 우선, 태블릿 대응 (필드 업무용)

## 8. 배포 구성

### docker-compose.yml 구성

- **app**: Next.js 애플리케이션 (포트 3000)
- **db**: Oracle XE 23 (포트 1521)

### 환경 변수

- `DATABASE_URL`: Oracle XE 접속 정보 (host:1521/XEPDB1)
- `NEXTAUTH_SECRET`: 인증 시크릿
- `NEXTAUTH_URL`: 서비스 URL
- `UPLOAD_DIR`: 첨부파일 저장 경로
