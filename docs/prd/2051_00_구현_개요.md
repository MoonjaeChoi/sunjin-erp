## 구현 개요

본 구현 계획은 sunjin-erp의 "장애 현황 관리" 모듈을 **4개 계층 18개 작업 단위**로 분해하여 순차적으로 구현하는 방식을 제시한다.

### 핵심 기능

* **장애 접수**: 고객사별 IT 장애 신규 등록 (자동 상태: INTAKE, 기본 is_public=false)
* **담당자 할당**: RBAC 기반 부서 제약 담당자 배정
* **처리 기록**: 처리 방법(원격/전화/현장), 소요 시간(분 단위 실시간 포맷팅), 처리 결과
* **파일 첨부**: 완료 리포트 등 최대 5개 문서 첨부 (이중 검증)
* **상태 관리**: INTAKE → IN_PROGRESS → COMPLETED 단방향, ADMIN만 COMPLETED 롤백 가능
* **공개 여부 제어**: is_public 플래그로 부서원 조회 범위 제한
* **RBAC 적용**: ADMIN(전체), MANAGER(같은 부서만), USER(제한적 조회만)

## 핵심 구현 포인트

### 1. is_public 기반 행 필터링 (RLS)

**API GET /issues 필터링 로직:**
```
ADMIN:      모든 행 반환
MANAGER:    assigned_to_id 부서 = 세션 부서 AND (assigned_to_id IS NOT NULL)
USER:       created_by_id = 세션 user_id
            OR assigned_to_id = 세션 user_id
            OR (is_public = true AND assigned_to_id의 부서 = 세션 부서)
```

### 2. ON DELETE RESTRICT 정책

**Issue 삭제 전 필수 조건:**
- IssueAttachment 테이블에 해당 issue_id 없어야 함
- 파일 있으면 409 Conflict 응답 + "먼저 첨부파일을 삭제하세요" 메시지
- **증거 보존을 위한 강제 정책**

### 3. 처리 시간 포맷팅 (분 → 시간:분)

**입력**: treatment_time_minutes (1~1440 숫자)
**포맷**:
- 150분 → "약 2시간 30분"
- 60분 → "약 1시간"
- 45분 → "약 45분"
- 1분 → "약 1분"

### 4. 상태 롤백 (ADMIN만)

**조건:**
- 현재 status = COMPLETED
- 역할 = ADMIN
- 롤백 후 status = IN_PROGRESS
- IssueHistory 기록: change_type = STATUS_ROLLBACK

### 5. MANAGER 부서 제약

**허용 동작:**
- 같은 부서 담당자인 Issue만 조회/수정
- 부서 내 직원에게만 담당자 할당
- IN_PROGRESS 상태에서도 부서 내 담당자 변경 가능
- 다른 부서 직원 할당 시 400 Bad Request

### 6. 파일 첨부 이중 검증

**프론트엔드:**
- 파일 선택 시 즉시 검증 (MIME type, 크기)
- 오류 시 toast 알림 + 즉시 피드백

**서버:**
- 업로드 시 재검증 (보안)
- MIME type, 확장자 화이트리스트 확인
- 파일 크기 재검증
- 장애당 파일 개수 확인
