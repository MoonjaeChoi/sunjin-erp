## 자원 분류

### 1. 공유 가능 자원 (기존 시스템과 함께 사용)

기존 시스템에 영향을 주지 않으면서 sunjin-erp가 함께 사용할 수 있는 자원입니다.

| 자원 | 공유 방식 | 조건 |
|------|-----------|------|
| **Oracle Database XE 인스턴스** | 동일 인스턴스, 별도 스키마 | `sunjin_admin` 사용자로 격리 |
| **Docker Engine** | 동일 Docker 데몬 | 별도 네트워크로 격리 |
| **Prometheus** | 동일 인스턴스, 별도 scrape target | sunjin-erp job 추가 |
| **Grafana** | 동일 인스턴스, 별도 대시보드 | sunjin-erp 폴더 분리 |
| **Loki** | 동일 인스턴스, 별도 label | `app=sunjin-erp` label |
| **하드웨어 (CPU/RAM/Storage)** | 물리적 공유 | 리소스 limit 설정 필수 |

#### Oracle DB 공유 상세

```
Oracle XE (Port 1521)
├── ocr_admin (기존) ─── en-zine 스키마, zine-alpaca 스키마
└── sunjin_admin (신규) ─── sunjin-erp 스키마 (완전 격리)
```

- 기존 `ocr_admin` 사용자/스키마에는 접근 불가
- `sunjin_admin` 사용자를 별도 생성하여 권한 격리
- 테이블스페이스 분리 권장 (quota 관리 가능)

#### 모니터링 스택 공유 상세

```yaml
# Prometheus scrape config 추가
- job_name: 'sunjin-erp'
  static_configs:
    - targets: ['sunjin-erp-app:3200']
```

| 포트 | 서비스 | 비고 |
|------|--------|------|
| 3200 | sunjin-erp Next.js App | 메인 애플리케이션 |

#### Docker 구성

```yaml
# sunjin-erp docker-compose.yml
networks:
  sunjin-network:
    driver: bridge
    ipam:
      config:
        - subnet: 172.22.0.0/16

services:
  app:
    ports:
      - "3200:3000"  # 내부 3000 → 외부 3200
    networks:
      - sunjin-network
    deploy:
      resources:
        limits:
          cpus: '3.0'
          memory: 8G
```

## 배포 시 주의사항

1. **포트 충돌 방지**: sunjin-erp는 반드시 3200 포트 사용 (3000은 기존 점유)

5. **모니터링 라벨 구분**: 로그/메트릭에 `app=sunjin-erp` 라벨 필수 부착
