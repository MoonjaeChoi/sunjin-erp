### 3.1 현재: Direct oracledb 연결 (`src/lib/db-direct.ts`)

**SELECT 쿼리 실행**

```typescript
import { executeQuery } from '@/lib/db-direct';

export async function GET(request: NextRequest) {
  try {
    const result = await executeQuery(
      `SELECT * FROM EMPLOYEE WHERE "id" = :id`,
      { id: 1 }
    );
    return NextResponse.json(result.rows);
  } catch (error) {
    console.error('Error:', error);
    return NextResponse.json({ error: 'Internal server error' }, { status: 500 });
  }
}
```

**INSERT/UPDATE/DELETE 실행**

```typescript
import { executeUpdate } from '@/lib/db-direct';

export async function POST(request: NextRequest) {
  try {
    const { name, email } = await request.json();

    await executeUpdate(
      `INSERT INTO EMPLOYEE (name, email) VALUES (:name, :email)`,
      { name, email }
    );

    return NextResponse.json({ success: true }, { status: 201 });
  } catch (error) {
    console.error('Error:', error);
    return NextResponse.json({ error: 'Internal server error' }, { status: 500 });
  }
}
```

## 4. Oracle 연결 문제 해결

### 4.1 Connection String 형식

**올바른 형식**
```
192.168.75.194:1521/FREEPDB1
```

**문제가 되는 형식**
```
192.168.75.194:1521:FREEPDB1  (❌ 콜론 사용)
localhost:1521/XE           (❌ 서비스명 오류)
```

### 4.2 열 식별자 케이싱 규칙 ⚠️ 중요

Oracle에서 식별자(테이블명, 컬럼명)는 **따옴표 사용 여부**에 따라 대소문자 처리가 달라집니다.

#### Oracle 식별자 처리 규칙

| 표기 방식 | Oracle 저장 방식 | 예시 |
|-----------|------------------|------|
| 따옴표 없음 (권장) | 자동 대문자 변환 | `id` → `ID` |
| 따옴표 있음 | 입력 그대로 저장 | `"id"` → `id` (소문자) |

#### 현재 테이블별 컬럼 케이싱 (2026-01-28 기준)

| 테이블 | 컬럼 케이싱 | 쿼리 작성 방식 |
|--------|-------------|----------------|
| **EMPLOYEE** | 대문자 | `E.ID`, `E.NAME`, `E.DEPARTMENT_ID` |
| **ACCOUNT** | 대문자 | `A.ID`, `A.USERNAME`, `A.ROLE` |
| **DEPARTMENT** | 대문자 | `D.ID`, `D.NAME`, `D.CODE` |
| **POSITION** | 대문자 | `P.ID`, `P.NAME`, `P.LVL` |
| **CUSTOMER** | 소문자 따옴표 | `"id"`, `"name"`, `"deleted_at"` |
| **ISSUE** | 대문자 | `ID`, `CUSTOMER_ID`, `STATUS` |
| **PROJECT** | 대문자 | `ID`, `PROJECT_NAME`, `STATUS` |
| **MAINTENANCE_CONTRACT** | 소문자 따옴표 | `"id"`, `"contract_name"` |

#### ⚠️ ORA-00904 에러 방지

```sql
-- ❌ 에러: ORA-00904 invalid identifier
-- EMPLOYEE 테이블은 대문자 컬럼 사용
SELECT E."department_id" FROM EMPLOYEE E

-- ✅ 정상 동작
SELECT E.DEPARTMENT_ID FROM EMPLOYEE E
```

### 4.3 JOIN 시 테이블별 케이싱 주의

```typescript
// ✅ 올바른 JOIN 쿼리 (테이블별 케이싱 확인 필수)
const query = `
  SELECT
    E.ID,
    E.NAME,
    E.DEPARTMENT_ID,
    D.NAME AS DEPARTMENT_NAME,
    c."name" AS CUSTOMER_NAME
  FROM EMPLOYEE E
  LEFT JOIN DEPARTMENT D ON D.ID = E.DEPARTMENT_ID
  LEFT JOIN CUSTOMER c ON c."id" = E.CUSTOMER_ID
`;
```

### 4.4 테이블 별칭(Alias) 규칙

Oracle에서 테이블 별칭도 동일한 규칙 적용:

```sql
-- ✅ 권장: 대문자 별칭 (따옴표 없이)
SELECT E.ID FROM EMPLOYEE E

-- ⚠️ 주의: 소문자 별칭은 대문자로 자동 변환됨
SELECT e.ID FROM EMPLOYEE e  -- e → E로 변환되어 동작

-- ❌ 비권장: 따옴표로 소문자 별칭 강제
SELECT "e".ID FROM EMPLOYEE "e"  -- 혼란 유발
```

## 5. 테이블 생성 및 스키마 확장 가이드

### 5.1 ⚠️ 2091 사례 교훈 (2026-01-28)

#### 발생한 문제

2091 직원관리 모듈 마이그레이션에서 다음 오류들이 발생:

| 오류 | 원인 | 영향 |
|------|------|------|
| ORA-00904 | 컬럼명 케이싱 불일치 (소문자 vs 대문자) | 11개 API 500 에러 |
| 401 Unauthorized | ACCOUNT 테이블 분리 후 데이터 미이관 | 로그인 불가 |
| 403 Forbidden | API 권한 설정 미조정 | 기능 접근 불가 |

#### 근본 원인

```
기존 EMPLOYEE 테이블          →    신규 구조
├── "id" (소문자 따옴표)             ├── EMPLOYEE.ID (대문자)
├── "username"                      ├── ACCOUNT.USERNAME (분리됨)
├── "password_hash"                 ├── ACCOUNT.PASSWORD_HASH (분리됨)
├── "role"                          ├── ACCOUNT.ROLE (분리됨)
└── "department_id"                 └── EMPLOYEE.DEPARTMENT_ID (대문자)
```

### 5.2 신규 테이블 생성 시 필수 체크리스트

#### ✅ 테이블 생성 전

```markdown
□ 컬럼명은 대문자 미따옴표 형식 사용 (Oracle 표준)
□ 기존 테이블과 JOIN할 경우 양쪽 케이싱 확인
□ 외래키 참조 컬럼의 케이싱 일치 확인
□ 시퀀스명 규칙: {TABLE_NAME}_ID_SEQ
```

#### ✅ 마이그레이션 작성 시

```typescript
// ✅ 권장: 대문자 미따옴표 (Oracle 자동 대문자 변환)
await queryRunner.query(`
  CREATE TABLE NEW_TABLE (
    ID NUMBER PRIMARY KEY,
    NAME VARCHAR2(100) NOT NULL,
    DEPARTMENT_ID NUMBER,
    CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    DELETED_AT TIMESTAMP
  )
`);

// ❌ 비권장: TypeORM createTable (소문자 따옴표 생성됨)
await queryRunner.createTable(new Table({
  name: 'NEW_TABLE',
  columns: [{ name: 'id', type: 'NUMBER' }]  // → "id" 소문자로 생성됨
}));
```

#### ✅ API 작성 시

```typescript
// 새 테이블 쿼리 시 반드시 컬럼 케이싱 확인
const result = await executeQuery(`
  SELECT
    NT.ID,              -- 대문자 테이블은 대문자 컬럼
    NT.NAME,
    c."id",             -- 소문자 테이블은 따옴표 사용
    c."name"
  FROM NEW_TABLE NT
  LEFT JOIN CUSTOMER c ON c."id" = NT.CUSTOMER_ID
`);
```

### 5.3 현재 스키마 구조 (인증 관련)

#### EMPLOYEE 테이블 (직원 정보)

```sql
-- 모든 컬럼 대문자
ID              NUMBER PRIMARY KEY
NAME            VARCHAR2(50)
EMAIL           VARCHAR2(100)
PHONE           VARCHAR2(20)
JOB_TITLE       VARCHAR2(100)
DEPARTMENT_ID   NUMBER (FK → DEPARTMENT.ID)
POSITION_ID     NUMBER (FK → POSITION.ID)
MANAGER_ID      NUMBER (FK → EMPLOYEE.ID)
HIRED_AT        TIMESTAMP
BIRTHDAY        TIMESTAMP
CREATED_AT      TIMESTAMP
CREATED_BY_ID   NUMBER
UPDATED_AT      TIMESTAMP
UPDATED_BY_ID   NUMBER
DELETED_AT      TIMESTAMP
```

#### ACCOUNT 테이블 (인증 정보 - EMPLOYEE와 분리)

```sql
-- 모든 컬럼 대문자
ID                  NUMBER PRIMARY KEY
EMPLOYEE_ID         NUMBER (FK → EMPLOYEE.ID)
USERNAME            VARCHAR2(50) UNIQUE
PASSWORD_HASH       VARCHAR2(200)
ROLE                VARCHAR2(20) -- 'ADMIN', 'MANAGER', 'USER'
IS_ACTIVE           NUMBER(1)    -- 1: 활성, 0: 비활성
LAST_LOGIN_AT       TIMESTAMP
PASSWORD_CHANGED_AT TIMESTAMP
CREATED_AT          TIMESTAMP
UPDATED_AT          TIMESTAMP
DELETED_AT          TIMESTAMP
```

#### 인증 쿼리 예시 (auth.ts)

```typescript
// ACCOUNT + EMPLOYEE 조인 필수
const result = await connection.execute(`
  SELECT
    e.ID,
    e.NAME,
    a.USERNAME,
    a.PASSWORD_HASH,
    a.ROLE,
    e.DEPARTMENT_ID
  FROM ACCOUNT a
  JOIN EMPLOYEE e ON a.EMPLOYEE_ID = e.ID
  WHERE a.USERNAME = :username
    AND a.IS_ACTIVE = 1
    AND a.DELETED_AT IS NULL
    AND e.DELETED_AT IS NULL
`);
```
