## 2. 확인된 테이블 스키마

### 2.1 EMPLOYEE (직원)

**열 케이싱**: 소문자 (`"id"`, `"username"`, 등)

```sql
CREATE TABLE EMPLOYEE (
  "id" NUMBER PRIMARY KEY,
  "name" VARCHAR2(255) NOT NULL,
  "username" VARCHAR2(100) NOT NULL,
  "password_hash" VARCHAR2(255) NOT NULL,
  "email" VARCHAR2(255),
  "role" VARCHAR2(50),
  "department_id" NUMBER,
  "position" VARCHAR2(100),
  "created_at" TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL,
  "updated_at" TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL,
  "deleted_at" TIMESTAMP
);

-- 인덱스
CREATE INDEX IDX_EMPLOYEE_USERNAME ON EMPLOYEE("username");
CREATE INDEX IDX_EMPLOYEE_DELETED_AT ON EMPLOYEE("deleted_at");
```

**역할 (Role) 기준**
- ADMIN: 시스템 관리자
- MANAGER: 부서 관리자
- USER: 일반 사용자

**쿼리 예시**
```sql
-- Kim 사용자 조회
SELECT "id", "name", "username", "password_hash", "role", "department_id"
FROM EMPLOYEE
WHERE "username" = 'kim' AND "deleted_at" IS NULL;
```

### 2.3 ISSUE (장애 관리)

**열 케이싱**: 대문자 (`"ID"`, `"CUSTOMER_ID"`, 등) ⚠️

```sql
CREATE TABLE ISSUE (
  ID NUMBER DEFAULT ISSUE_SEQ.NEXTVAL PRIMARY KEY,
  CUSTOMER_ID NUMBER NOT NULL,
  TITLE VARCHAR2(255) NOT NULL,
  DESCRIPTION CLOB,
  SEVERITY VARCHAR2(20) DEFAULT 'CRITICAL' NOT NULL,
  STATUS VARCHAR2(20) DEFAULT 'INTAKE' NOT NULL,
  IS_PUBLIC NUMBER(1) DEFAULT 0 NOT NULL,
  CREATED_BY_ID NUMBER NOT NULL,
  ASSIGNED_TO_ID NUMBER,
  TREATMENT_METHOD VARCHAR2(50),
  TREATMENT_TIME_MINUTES NUMBER CHECK (TREATMENT_TIME_MINUTES IS NULL
                                    OR (TREATMENT_TIME_MINUTES >= 1 AND TREATMENT_TIME_MINUTES <= 1440)),
  TREATMENT_RESULT CLOB,
  CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL,
  COMPLETED_AT TIMESTAMP,
  UPDATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL,
  DELETED_AT TIMESTAMP,
  CONSTRAINT FK_ISSUE_CUSTOMER FOREIGN KEY (CUSTOMER_ID) REFERENCES CUSTOMER(id) ON DELETE RESTRICT,
  CONSTRAINT FK_ISSUE_CREATED_BY FOREIGN KEY (CREATED_BY_ID) REFERENCES EMPLOYEE(id) ON DELETE RESTRICT,
  CONSTRAINT FK_ISSUE_ASSIGNED_TO FOREIGN KEY (ASSIGNED_TO_ID) REFERENCES EMPLOYEE(id) ON DELETE SET NULL
);

-- 시퀀스
CREATE SEQUENCE ISSUE_SEQ START WITH 1 INCREMENT BY 1;

-- 인덱스
CREATE INDEX IDX_ISSUE_CUSTOMER_ID ON ISSUE(CUSTOMER_ID);
CREATE INDEX IDX_ISSUE_CREATED_BY_ID ON ISSUE(CREATED_BY_ID);
CREATE INDEX IDX_ISSUE_ASSIGNED_TO_ID ON ISSUE(ASSIGNED_TO_ID);
CREATE INDEX IDX_ISSUE_STATUS ON ISSUE(STATUS);
CREATE INDEX IDX_ISSUE_DELETED_AT ON ISSUE(DELETED_AT);
```

**Severity 값**
- CRITICAL: 긴급 (24시간 대응)
- HIGH: 높음 (48시간 대응)
- MEDIUM: 중간 (72시간 대응)
- LOW: 낮음 (일주일)

**Status 값**
- INTAKE: 접수 (초기 상태)
- IN_PROGRESS: 처리 중
- COMPLETED: 완료

**Treatment Method**
- REMOTE: 원격지원
- PHONE: 전화지원
- ONSITE: 방문지원

**쿼리 예시**
```sql
-- 올바른 쿼리 (quoted uppercase)
SELECT "ID", "CUSTOMER_ID", "TITLE", "STATUS"
FROM ISSUE
WHERE "DELETED_AT" IS NULL
ORDER BY "CREATED_AT" DESC;

-- ❌ 에러: ORA-00904
SELECT "id", "customer_id", "title", "status"
FROM ISSUE
WHERE "deleted_at" IS NULL;
```

## 4. 열 케이싱 규칙 (중요)

### 4.1 문제: 테이블별 다른 케이싱

Oracle에서 **quoted identifier** 사용 시 생성된 케이싱이 유지됩니다.

```sql
-- 생성 시
CREATE TABLE ISSUE (ID NUMBER, CUSTOMER_ID NUMBER)
-- → 내부적으로 대문자로 저장됨

-- 쿼리 시
SELECT "ID" FROM ISSUE          -- ✓ 성공
SELECT "id" FROM ISSUE          -- ❌ ORA-00904: "id": invalid identifier
```

### 4.2 각 테이블의 실제 열 이름

| 테이블 | 쿼리 시 열 이름 | 예시 |
|--------|----------------|------|
| EMPLOYEE | 소문자 (quoted) | `"id"`, `"username"`, `"password_hash"`, `"department_id"`, `"deleted_at"` |
| CUSTOMER | 소문자 (quoted) | `"id"`, `"name"`, `"deleted_at"` |
| ISSUE | 대문자 (quoted) | `"ID"`, `"CUSTOMER_ID"`, `"CREATED_BY_ID"`, `"DELETED_AT"` |

### 4.3 JOIN 작성 시 주의

```typescript
// ✓ 올바른 예 (ISSUE-CUSTOMER 조인)
const query = `
  SELECT
    "i"."ID",           // ISSUE: 대문자
    "i"."CUSTOMER_ID",  // ISSUE: 대문자
    "c"."id",           // CUSTOMER: 소문자
    "c"."name"          // CUSTOMER: 소문자
  FROM ISSUE "i"
  LEFT JOIN CUSTOMER "c" ON "c"."id" = "i"."CUSTOMER_ID"
`;
```

## 5. 소프트 삭제 (Soft Delete) 규칙

모든 테이블에는 `deleted_at` 컬럼이 있으며, 물리적 삭제 대신 이 컬럼에 타임스탐프를 설정합니다.

```sql
-- 물리적 삭제 금지
DELETE FROM ISSUE WHERE ID = 1;  -- ❌

-- 소프트 삭제 사용
UPDATE ISSUE SET DELETED_AT = CURRENT_TIMESTAMP WHERE ID = 1;  -- ✓
```

**쿼리에서 삭제된 항목 제외**
```sql
-- 모든 조회 쿼리에서 필수
SELECT * FROM ISSUE WHERE "DELETED_AT" IS NULL;
```

## 6. 외래키 제약사항

**ON DELETE 규칙**: `CASCADE DELETE` 금지, `RESTRICT` 또는 `SET NULL` 사용

```sql
-- ✓ 올바른 설정
CONSTRAINT FK_ISSUE_CUSTOMER
  FOREIGN KEY (CUSTOMER_ID)
  REFERENCES CUSTOMER(id)
  ON DELETE RESTRICT;  -- 참조 중인 데이터 있으면 삭제 불가

-- ❌ 금지
ON DELETE CASCADE  -- 불가 (참조 데이터 자동 삭제)
```

## 12. 문제 해결

### 12.1 ORA-00904: invalid identifier

**원인**: 열 이름 케이싱 불일치

```sql
-- ❌ 잘못된 쿼리
SELECT "id" FROM ISSUE;  -- ISSUE 테이블은 "ID" (대문자)

-- ✓ 올바른 쿼리
SELECT "ID" FROM ISSUE;
```

**해결책**: 테이블의 실제 열 이름 케이싱 확인 후 사용

### 12.2 ORA-00942: Table or view does not exist

**원인**: 테이블이 없거나 스키마명 오류

```sql
-- 테이블 존재 확인
SELECT * FROM USER_TABLES WHERE TABLE_NAME = 'ISSUE';
```

### 12.3 ORA-01407: cannot update to NULL

**원인**: NOT NULL 컬럼에 NULL 값 설정

```sql
-- NOT NULL인 컬럼 확인
SELECT COLUMN_NAME, NULLABLE
FROM USER_TAB_COLUMNS
WHERE TABLE_NAME = 'ISSUE' AND NULLABLE = 'N';
```
