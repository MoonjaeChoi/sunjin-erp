## 8. 컬럼 케이싱 규칙 요약

### 8.1 테이블별 케이싱

| 케이싱 | 테이블 | 쿼리 작성 방식 |
|--------|--------|----------------|
| **대문자** | ACCOUNT, EMPLOYEE, DEPARTMENT, POSITION, EMPLOYEE_HISTORY, ISSUE, INVENTORY, INVENTORY_HISTORY, MAINTENANCE_CONTRACT, MAINTENANCE_CONTRACT_ATTACHMENT, MAINTENANCE_CONTRACT_HISTORY | `SELECT ID, NAME FROM TABLE` |
| **소문자** | PROJECT, PROJECT_ATTACHMENT, TASK, TECH_SUPPORT | `SELECT "id", "name" FROM TABLE` |
| **혼합** | CUSTOMER, CUSTOMER_CONTACT, CUSTOMER_HISTORY | `SELECT "id", CODE FROM TABLE` |

### 8.2 쿼리 작성 예시

```sql
-- 대문자 테이블 (EMPLOYEE)
SELECT E.ID, E.NAME, E.DEPARTMENT_ID FROM EMPLOYEE E

-- 소문자 테이블 (PROJECT)
SELECT "id", "project_name", "status" FROM PROJECT

-- 혼합 테이블 (CUSTOMER) - 주의 필요
SELECT "id", "name", CODE, EMAIL FROM CUSTOMER
```

## 9. 소프트 삭제 규칙

모든 테이블에 `DELETED_AT` (또는 `deleted_at`) 컬럼이 있으며, 물리적 삭제 대신 타임스탬프를 설정합니다.

```sql
-- 물리적 삭제 금지
DELETE FROM EMPLOYEE WHERE ID = 1;  -- ❌

-- 소프트 삭제 사용
UPDATE EMPLOYEE SET DELETED_AT = CURRENT_TIMESTAMP WHERE ID = 1;  -- ✅

-- 조회 시 삭제된 항목 제외
SELECT * FROM EMPLOYEE WHERE DELETED_AT IS NULL;
```
